# Adaptive Radial Pulse Acquisition

自适应桡动脉脉搏数字化采集与客观分析系统。

> 仓库名保留历史名称；当前项目主体不是中医诊断系统。

> 当前状态：D0–D3数字基线已完成并冻结；项目处于M1“真实数据闭环”。当前主要实施M1-P真实接入前软件就绪，同时并行进行H1-A采购调研。默认在M1-PV和BOM评审通过后正式下单。本项目只输出客观脉搏参数和工程验证结果，不输出脉象、证候、疾病或治疗结论。

## 项目核心

项目不是以持续增加硬件为终点，而是构建以下可追溯闭环：

```mermaid
flowchart LR
    A["DAQ 采集与执行<br/>模拟或真实原始数据"] --> B["SP 信号处理<br/>完整性、质量、滤波、逐搏"]
    B --> C["APP 分析软件<br/>会话、重放、参数、报告"]
    C --> D["INT 自适应决策<br/>接受、重采、换位、停止"]
    D --> A
```

| 主线 | 核心职责 | 当前目标 |
|---|---|---|
| DAQ | 数据源、传感器、ADC、MCU、探头、接触力和执行器 | 先冻结统一接口；后续用H1真实硬件替换模拟数据源 |
| SP | 完整性、工程单位、质量、滤波、逐搏和特征 | S1-pre预实现后，用H1真实数据校准为S1 |
| APP | 会话、原始落盘、重放、可视化、参数和报告 | A1-pre预实现后，接入真实设备成为A1 |
| INT | 根据安全、完整性、质量和历史决定下一步动作 | I1-pre规则预实现后，用真实结果复验为I1 |

信号质量不通过时，APP必须阻断正式参数；INT不得覆盖设备安全状态机和人工停止。

## 当前实施：M1-P＋H1-A并行

```text
M1-P真实接入前软件就绪（主要实施）
├─ M1-P0 数据契约与Schema（已完成）
├─ M1-P1 多通道真实风格模拟器（已完成并合并）
├─ M1-P2 SP-S1-pre信号处理（P2A/P2B/P2C已完成；P2D未开始）
├─ M1-P3 APP-A1-pre分析软件
├─ M1-P4 INT-I1-pre决策规则
├─ M1-P5 模拟场景与验收矩阵
└─ M1-PV 软件就绪验收

H1-A采购调研（并行）
└─ 型号、供应商、价格、交期、原理图、验证假设和备选方案
```

M1-P1当前包含：18个模拟案例、正式会话输出、Replay、CLI与综合验收。仍为合成数据；真实阈值待H1校准。M1-P1完成不等于M1-P、H1或M1完成。

默认顺序：

```text
M1-PV通过
＋ H1-A BOM与电气风险评审通过
→ 正式下单
→ H1-B到货与电气验收
→ H1-C真实数据链路
→ SP-S1 / APP-A1 / INT-I1真实校准与复验
→ H1手动单点与重戴
→ M1综合验收
```

M1-P不是新的长期数字阶段。它只把硬件接入前能够确定的软件结构和失败行为提前完成，不产生真实硬件或人体性能结论。

## D0–D3数字基线

D0–D3已经形成并冻结：

- 小端二进制协议、CRC、确定性合成脉搏和多载荷模拟；
- 原始帧优先落盘、会话、事件、完整性统计和重放；
- 基线处理、峰检测、心率、压力分段和质量门控；
- 设备抽象、虚拟串口、握手、断连和重连；
- 版本化标定、多压力数字实验、漂移/迟滞/削顶/伪影注入；
- 自动施压被控对象、PID、安全状态机、14类故障、ABORT和卸载闭环；
- FastAPI、React/TypeScript和GitHub Actions正式验收。

D3正式冻结标签：`d3-v1.0.0`。

这些成果只证明数字环境内的软件、控制和安全行为成立，不能替代真实硬件验证。

## M1完成标准

M1只有在以下全部成立后才能完成：

- M1-P软件就绪验收通过；
- H1真实单点实体证据包通过；
- SP-S1真实完整性、滤波、逐搏、质量和PPG对齐通过；
- APP-A1真实会话、落盘、重放、展示和基础参数通过；
- INT-I1真实接受、重采、换位、复核和停止路径通过；
- 获得30–60秒真实记录并与参考PPG量化对照；
- 完全重戴至少3次并保留成功与失败数据；
- 每个正式结果可追溯到原始数据、硬件、固件、校准、代码和配置版本。

仅M1-P通过、仅接通硬件、仅看到波形、仅完成算法或仅完成界面都不能宣称M1完成。

## 本地运行

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"
python -m pytest -q
python -m unittest discover -s tests -v
python scripts/generate_d3_acceptance.py
python scripts/generate_m1_p1_acceptance.py
python -m digital_pulse.m1_simulator list
pulse-simulator --output simulated-session.bin --forces 40 80 120
pulse-api
```

另开终端启动前端：

```bash
cd web
npm install
npm run dev
```

API默认位于`http://localhost:8000`，前端默认位于`http://localhost:5173`。

D0–D3中的载荷值和合成波形仅用于验证软件流程，不是人体安全压力或医学模型。

## 技术栈

- MCU：ESP32-S3开发板起步，出现明确瓶颈后再评估STM32；
- 固件：C/C++、PlatformIO；
- 采集与分析：Python、FastAPI、NumPy、SciPy、pandas、scikit-learn；
- 界面：React、TypeScript、WebSocket/SSE；
- 数据：原始二进制、Parquet/HDF5、SQLite/PostgreSQL；
- 硬件：KiCad；
- 结构：Fusion 360、SolidWorks或FreeCAD；
- 仿真：Python、LTspice/ngspice，必要时使用Simulink。
