# Adaptive Radial Pulse Acquisition

自适应桡动脉脉搏数字化采集与客观分析系统。

> 仓库名保留历史名称；当前项目主体不是中医诊断系统。

> 当前状态：D0、D1、D2已验收并合并；D3-A至D3-F已完成，当前进行D3-G集成与最终验收。H1真实硬件采购等待D3-G通过。本项目输出客观脉搏参数和工程验证结果，不输出脉象、证候、疾病或治疗结论。

## 项目核心：三层系统

本项目按照一条明确的数据可信链建设：

```mermaid
flowchart LR
    A["第一层：采集硬件<br/>把人体脉搏变成原始数字数据"] --> B["第二层：信号处理<br/>把原始数据变成可信标准信号"]
    B --> C["第三层：分析软件<br/>把可信信号变成参数、模型与报告"]
    C -->|质量不足、需要调压| A
```

| 系统层 | 主要组成 | 交付结果 |
|---|---|---|
| 采集硬件 | 探头、动态传感器、载荷传感器、模拟前端、ADC、MCU、施压机构 | 带时间戳、位置、接触力和设备状态的原始数字脉搏数据 |
| 信号处理 | 校准、完整性检查、质量控制、滤波、伪影检测、逐搏切分 | 可信波形、质量标签、单搏片段和客观特征 |
| 分析软件 | 会话管理、实时界面、数据存储、客观参数、重复性和报告 | 心率、节律、形态、压力响应、质量和工程统计 |

建设顺序不能颠倒：采集数据不可靠时不输出客观参数；信号质量不通过时，分析软件必须拒绝生成正式结果并提示重采。

本地运行：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -e .
python -m unittest discover -s tests -v
pulse-simulator --output simulated-session.bin --forces 40 80 120
pulse-api
```

另开终端启动前端：

```bash
cd web
npm install
npm run dev
```

API 默认位于 `http://localhost:8000`，前端默认位于 `http://localhost:5173`。

这些载荷值和合成波形仅用于验证软件流程，不是人体安全压力或医学模型。

## 阶段性实物目标

H1–H4逐步完成单点“关部”桌面式原型；其中H1先完成手动单点采集，H3才加入自动施压：

1. 手动定位桡动脉；
2. 同步采集动态脉搏波与静态接触力；
3. 通过丝杆执行机构完成分层自动施压；
4. 在电脑端实时显示并保存原始数据；
5. 完成质量判断、逐搏切分和客观参数；
6. 用多人、重复佩戴实验评价有效信号率、压力控制误差、心率误差和重测一致性。

自动寻脉和空间定位属于后续工程阶段；中医脉象研究是需要专业合作、伦理和标注的可选外部扩展，不影响项目主体完成。

## 技术栈

- MCU：先用ESP32-S3开发板快速验证，出现明确瓶颈后再评估STM32；
- 固件：C/C++、PlatformIO，后期按需要引入FreeRTOS；
- 采集与分析服务：Python、FastAPI；
- 界面：React、TypeScript、WebSocket/SSE；
- 数据：Parquet/HDF5、SQLite/PostgreSQL；
- 算法：NumPy、SciPy、pandas、scikit-learn，数据充分后使用PyTorch；
- 硬件设计：KiCad；
- 结构设计：Fusion 360、SolidWorks或FreeCAD；
- 仿真：Python、LTspice/ngspice，必要时使用Simulink。

## 安全声明
