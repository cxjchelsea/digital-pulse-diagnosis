# Digital Pulse Diagnosis

面向桡动脉脉搏数字化的自适应寻脉与多压力采集系统。

> 当前状态：概念验证与工程规划阶段。仓库中的诊断、脉象识别和性能指标均为研究目标，除非附有实验记录，否则不代表已经实现或具备医疗有效性。

## 项目定位

本项目首先解决“怎样稳定、可重复地获得可信的桡动脉多压力脉搏波”，再研究信号分析和脉象辅助识别。它不是在缺少临床证据的情况下直接输出疾病诊断的消费级设备。

项目适合逐步展示以下能力：

- 传感器、模拟前端、ADC与MCU数据采集；
- 自动施压、载荷反馈和安全状态机；
- 串口协议、实时上位机和数据管理；
- 生理信号滤波、质量评价、逐搏分析；
- 多压力响应建模和后续AI脉象研究；
- 可复现的实验、验证与医疗安全边界。

## 首个可交付目标

完成单点“关部”桌面式原型：

1. 手动定位桡动脉；
2. 同步采集动态脉搏波与静态接触力；
3. 通过丝杆执行机构完成分层自动施压；
4. 在电脑端实时显示并保存原始数据；
5. 计算心率、逐搏形态和信号质量；
6. 用多人、重复佩戴实验评价有效信号率、压力控制误差、心率误差和重测一致性。

自动寻脉、寸关尺阵列、脉象识别和医生协作数据集属于后续阶段。

## 建议技术栈

- MCU：先用ESP32-S3开发板快速验证；实时性或模拟性能出现瓶颈后再评估STM32；
- 固件：C/C++，PlatformIO，后期按需要引入FreeRTOS；
- 上位机：Python采集服务 + FastAPI，React/TypeScript实时界面；
- 数据：原始采集文件优先使用Parquet/HDF5，元数据使用SQLite/PostgreSQL；
- 算法：NumPy、SciPy、pandas、scikit-learn、PyTorch；
- 硬件设计：KiCad；
- 结构设计：Fusion 360、SolidWorks或FreeCAD；
- 仿真：Python信号模拟、LTspice/ngspice电路仿真、必要时Simulink控制仿真。

## 阶段门

| 阶段 | 关键结果 | 通过条件 |
|---|---|---|
| P0 软件仿真 | 模拟波形、协议、实时显示 | 可稳定回放并自动测试 |
| P1 手动单点采集 | 真实桡动脉原始波形 | 不削顶，心搏可辨，参考心率一致 |
| P2 接触力同步 | 压力—波形联合数据 | 可重复获得压力响应曲线 |
| P3 自动施压 | 单探头压力闭环 | 满足安全、稳态误差和超调要求 |
| P4 自动寻脉 | 多点空间定位 | 达到预先冻结的寻脉成功率 |
| P5 AI研究 | 多标签脉象候选 | 受试者隔离的独立测试成立 |

完整计划见 [PROJECT_PLAN.md](docs/PROJECT_PLAN.md)。
