# P0阶段实施总方案

版本：0.1.0；状态：已通过P0合成环境验收；唯一执行入口。

## 1. 阶段目标

在没有真实硬件时，以设备模拟器代替采集硬件，完整打通“模拟采集→协议→原始落盘→信号处理→质量门控→分析API→Web展示→验收报告”，并冻结P1真实硬件必须遵守的接口。

## 2. 非目标

- 不采购完整硬件；不进行人体实验；不确定人体安全载荷；
- 不输出脉象、疾病或治疗建议；
- 不把合成信号指标写成真实设备性能；
- 不在P0冻结最终传感器、ADC、滤波频带和模型。

## 4. 执行顺序

1. 冻结P0需求和协议；
2. 模拟器按正式协议输出；
3. 采集服务先保存原始帧，再解析统计；
4. 信号流水线只处理ACQUIRE稳态窗口；
5. 质量不合格时阻断心率和幅值结果；
6. API生成会话并返回Manifest与报告；
7. Web仅展示P0研究结果和免责声明；
8. 完成故障注入和连续运行；
9. 形成验收报告，满足退出标准后进入P1。

## 5. 代码交付

- `src/digital_pulse/protocol.py`：协议；
- `waveform.py`、`device.py`：模拟器；
- `session.py`：采集、Manifest、事件和重放；
- `signal.py`、`pipeline.py`：质量门控和分析；
- `api.py`：FastAPI；
- `web/`：React分析界面；
- `tests/`：自动化验收。

## 6. 退出标准

- 全部自动测试通过；
- 30分钟模拟会话完整落盘和重放；
- CRC损坏、尾帧不完整、序号缺口和时间戳错误可识别；
- 同种子逐样本一致；
- 干净合成信号心率误差小于1 bpm；
- 无信号或质量失败时正式分析被阻断；
- API和React生产构建通过；
- README可复现；
- 形成P0验收报告；
- P1仍未确定的硬件参数有明确实验冻结方法。

## 7. 进入P1

P0通过后，才按`02-采集硬件/首批传感器选型实验方案.md`采购小批候选并制作手动单点原型。模拟器载荷40/80/120不得转换成人体载荷。

验收证据见`../05-验证与实验/P0阶段验收报告.md`。P0通过仅证明合成环境的软件闭环成立，不证明真实硬件、人体测量或医学性能。
