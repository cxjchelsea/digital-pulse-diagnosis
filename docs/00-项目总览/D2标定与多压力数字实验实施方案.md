# D2标定与多压力数字实验实施方案

版本：1.0.0  
状态：实施基线；本文件通过评审后按顺序编码。  
关联Issue：[D2-01 实现标定与多压力数字实验](https://github.com/cxjchelsea/digital-pulse-diagnosis/issues/12)

## 1. 阶段目标

D2在不购买硬件的条件下，建立“原始ADC计数—版本化标定—合成工程值—多压力稳态窗口—质量门控—压力响应—实验报告”的完整数字实验链。

D2需要证明：

1. 已知标定关系能够正确恢复合成工程值；
2. 标定缺失、过期、非法、越界或漂移时，软件能够识别并阻断正式结果；
3. 多压力实验的目标、稳定、采集和失败过程可配置、可重放；
4. 只有标定有效且质量合格的稳态窗口才能进入压力响应；
5. 相同输入、种子、标定和代码版本生成相同报告；
6. 原始数据、标定、配置、派生结果和报告之间可以追溯。

## 2. 证据边界

D2使用合成数据和合成标定关系，不证明：

- 真实ADC有效位数、零点、噪声或线性；
- 真实传感器灵敏度、迟滞、漂移或温度特性；
- 探头接触面积、真实力值或人体安全压力；
- 真实硬件的最佳载荷；
- 医学或脉象有效性。

D2的工程值单位统一使用：

- 动态脉搏：`pulse_au`；
- 接触载荷：`force_au`；
- 参考通道：`reference_au`。

`au`表示合成相对单位。D2禁止把它改写为N、g、mmHg或kPa。真实单位只能在H1使用可追溯参考器具标定后启用。

## 3. 输入、处理与输出

```mermaid
flowchart LR
    A["D1原始帧"] --> B["标定注册表"]
    B --> C["L1合成工程值"]
    C --> D["稳态窗口与质量门控"]
    D --> E["压力响应与候选评分"]
    E --> F["可追溯实验报告"]
```

### 3.1 输入

- D1协议v0原始数据帧；
- 会话Manifest和设备能力；
- 标定记录；
- 压力Profile；
- 合成故障配置；
- 算法参数和随机种子。

### 3.2 输出

- 不覆盖L0原始帧的L1工程值样本；
- 每个压力步骤的稳定性、质量和无效原因；
- 压力—幅值、压力—质量、压力—心率响应；
- 候选压力平台评分和推荐；
- 标定与实验报告；
- 完整的版本和输入证据链。

## 4. 标定模型

### 4.1 标定记录

建议定义不可变`CalibrationRecord`：

| 字段 | 类型 | 规则 |
|---|---|---|
| calibration_id | string | 全局唯一 |
| schema_version | string | D2首版为`1.0.0` |
| channel | enum | pulse、force、reference |
| model_type | enum | offset、affine、piecewise_linear |
| raw_points | list[float] | 原始ADC计数，严格递增 |
| engineering_points | list[float] | 合成工程值，与raw_points等长 |
| unit | string | D2只允许对应`*_au` |
| created_at_utc | datetime | UTC |
| valid_from_utc | datetime | UTC |
| valid_until_utc | datetime/null | 过期后禁止正式输出 |
| source | enum | synthetic、bench、device |
| generator_version | string/null | 合成标定必填 |
| checksum | string | 规范化内容SHA-256 |
| notes | string | 不作为算法输入 |

记录创建后不可原地修改；重新标定必须生成新ID。

### 4.2 三种流程

#### 零点标定

只估计offset。必须已有有效scale或参考模型，否则只能输出去零点后的ADC计数，不能声称完成工程单位转换。

#### 两点标定

使用仿射模型：

[
y=ax+b
]

两点的原始计数和工程值都必须不同，斜率必须有限且方向符合通道配置。

#### 多点标定

首版采用单调分段线性插值，不使用高阶多项式，避免端点振荡和不可解释外推。

- 原始点严格递增；
- 工程点必须按声明方向单调；
- 点数不少于3；
- 默认禁止超出标定范围外推；
- 边界外样本标记`out_of_range`并阻断对应窗口。

### 4.3 有效性检查

标定使用前依次检查：

1. Schema与必填字段；
2. checksum；
3. channel和unit匹配；
4. 时间有效期；
5. 点数、有限值和长度；
6. 单调性与斜率；
7. 当前原始值是否在有效范围；
8. Manifest引用的calibration_id是否存在。

任一硬性检查失败，不生成正式L1工程值，也不允许压力响应分析。

## 5. 标定状态与错误码

| 状态/错误 | 处理 |
|---|---|
| valid | 允许转换 |
| missing | 阻断，提示选择或生成标定 |
| expired | 阻断，保留原始数据 |
| checksum_mismatch | 阻断并记录完整性事件 |
| channel_mismatch | 阻断 |
| unit_mismatch | 阻断 |
| non_monotonic | 阻断 |
| invalid_coefficient | 阻断 |
| out_of_range | 对窗口阻断，不静默外推 |
| drift_suspected | 标记实验无效并建议重新标定 |
| calibration_changed | 中止当前实验；新标定只能用于新会话 |

错误必须进入事件日志、Manifest摘要、API响应和最终报告。

## 6. 多压力Profile

建议定义：

| 字段 | 说明 |
|---|---|
| profile_id/version | Profile身份与版本 |
| steps | 有序压力步骤 |
| target_force_au | 合成目标载荷 |
| approach_s | 目标切换后的过渡时间 |
| min_stable_s | 最短稳定持续时间 |
| acquire_s | 稳态采集时间 |
| tolerance_abs_au | 目标绝对容差 |
| tolerance_rate_au_s | 载荷变化率阈值 |
| timeout_s | 未稳定超时 |
| repeat_count | Profile重复次数 |
| seed | 合成随机种子 |

### 6.1 稳态判据

只有同时满足以下条件的连续窗口进入正式分析：

- 载荷与目标差不超过绝对容差；
- 载荷变化率不超过阈值；
- 持续时间达到`min_stable_s`；
- 无削顶、断线、运动伪影或协议错误；
- 标定有效且样本未越界。

不得仅按模拟器的`ACQUIRE`状态直接视为稳态；D2必须用数据重新验证稳态。

### 6.2 Profile约束

- 至少1个步骤，最多20个步骤；
- 目标值必须非负、有限；
- 时间参数必须非负，`acquire_s > 0`；
- D2允许升序、降序和往返Profile，用于验证迟滞；
- 默认示例40/80/120仍是`force_au`，不对应人体载荷。

## 7. 合成实验与故障注入

建议新增不可变`D2FaultConfig`，所有故障使用显式参数和种子。

| 故障 | 注入位置 | 预期结果 |
|---|---|---|
| zero_offset | 原始计数 | 有效标定后恢复 |
| gain_error | 原始计数 | 有效标定后恢复 |
| gaussian_noise | 原始计数 | 影响质量分数但保持可复现 |
| baseline_drift | 通道基线 | 触发漂移检测或质量下降 |
| hysteresis | 升/降载荷 | 报告加载/卸载差异 |
| nonlinearity | 标定关系 | 仿射模型残差升高；多点模型可恢复 |
| clipping | ADC边界 | 对应窗口无效 |
| motion_artifact | 指定时间段 | 对应窗口无效或降级 |
| sensor_disconnect | 指定时间段 | 阻断并记录事件 |
| calibration_missing | 注册表 | 全部工程值阻断 |
| calibration_expired | 时间检查 | 全部工程值阻断 |
| calibration_tampered | checksum | 完整性阻断 |
| never_stable | 压力响应 | 步骤超时且不进入分析 |

故障配置和随机种子必须写入Manifest，禁止在测试中依赖不可控随机性。

## 8. 压力响应与评分

### 8.1 每步结果

每个压力步骤至少输出：

- 目标值、实际均值、标准差和稳定时间；
- 有效/无效样本数；
- 标定状态；
- 质量标签、分数和原因；
- 心率及可用性；
- 脉搏幅值、上升时间、波宽和面积；
- 削顶率、伪影率和越界率；
- 加载或卸载方向；
- 是否允许进入总体评分。

### 8.2 响应曲线

- 压力—幅值；
- 压力—质量；
- 压力—形态；
- 压力—心率一致性；
- 往返Profile的迟滞差。

### 8.3 候选评分

首版只用于数字实验选择“采集质量较好的合成平台”，不声称人体最佳压力。

硬门控优先：

- 标定无效；
- 数据完整性失败；
- 未达到稳态；
- 质量为invalid/no_signal；
- 削顶或越界超过阈值。

通过硬门控后再按冻结权重评分。建议首版：

| 维度 | 权重 |
|---|---:|
| 信号质量 | 40% |
| 脉搏幅值（归一化） | 25% |
| 稳定性 | 20% |
| 有效窗口覆盖率 | 15% |

权重必须在运行实验前写入配置，报告中同时给出单项分数，不能只保留总分。

## 9. 数据与报告

### 9.1 会话目录增量

```text
session-id/
├── manifest.json
├── raw_frames.bin
├── events.jsonl
├── calibration/
│   ├── registry.json
│   └── applied.json
├── experiment/
│   ├── profile.json
│   └── fault_config.json
└── processed/
    ├── calibrated_samples.jsonl
    ├── stable_windows.json
    ├── pressure_response.json
    └── report.json
```

D2首版可使用JSON/JSONL保证透明和易调试；达到规模瓶颈后再增加Parquet，不把格式迁移作为D2前置条件。

### 9.2 报告Schema

报告至少包含：

- `schema_version`、`experiment_id`、`session_id`；
- 输入文件哈希；
- 协议、模拟器、代码和算法版本；
- calibration_id、checksum和状态；
- profile_id、完整参数和种子；
- 故障配置；
- 数据完整性摘要；
- 各压力步骤结果；
- 响应曲线数据；
- 候选评分和被淘汰原因；
- `analysis_allowed`；
- 限制与非医疗声明。

报告生成必须是纯派生过程：删除`processed/`后可以从L0、配置和标定完整重建。

## 10. 后端与前端

### 10.1 后端

建议新增：

- `POST /api/calibrations/validate`；
- `POST /api/experiments/d2/run`；
- `GET /api/experiments/{id}`；
- `GET /api/experiments/{id}/report`；
- `POST /api/experiments/{id}/replay`。

API必须区分：

- 400：配置或Schema非法；
- 409：标定状态或会话状态冲突；
- 422：可解析但实验条件无效；
- 500：未预期内部错误。

### 10.2 前端

D2页面最小交付：

1. 标定记录查看和有效性检查；
2. 压力Profile编辑；
3. 故障场景选择；
4. 运行与重放；
5. 每步稳态、质量和失败原因；
6. 压力响应曲线；
7. 报告下载；
8. 始终显示“合成相对单位、非真实硬件结果”。

D2不实现真实标定向导、串口端口选择或人体实验界面。

## 12. 工作包与实现顺序

| 工作包 | 内容 | 退出条件 |
|---|---|---|
| D2-A 契约冻结 | 标定、Profile、错误码、报告Schema | Schema示例评审通过 |
| D2-B 标定核心 | offset、affine、piecewise linear、注册表 | 正常和非法标定测试通过 |
| D2-C 实验生成 | 多压力Profile、升降载、稳定判据 | 步骤与窗口可重现 |
| D2-D 故障注入 | 漂移、迟滞、削顶、伪影、断线、标定故障 | 故障矩阵通过 |
| D2-E 分析报告 | 压力响应、硬门控、评分、重建 | 报告快照和重放一致 |
| D2-F API与Web | 配置、运行、状态、曲线、下载 | 端到端手动验收通过 |
| D2-G 集成验收 | 全量回归、长流、文档和报告 | D2退出条件全部满足 |

实现顺序固定为A→B→C→D→E→F→G。不得先做界面再补标定和门控。

## 14. 手动验收

1. 启动后端和前端；
2. 查看默认合成标定，确认单位为`*_au`；
3. 运行升序40/80/120 Profile；
4. 查看每步稳定、质量、特征和压力响应；
5. 使用相同种子重放，确认报告一致；
6. 注入过期标定，确认分析被阻断；
7. 注入削顶和运动伪影，确认只影响对应窗口；
8. 运行升降载Profile，查看迟滞结果；
9. 下载报告，核对标定、Profile、种子、代码版本和免责声明；
10. 确认界面没有N、kPa、人体安全或医学结论。

## 15. D2退出条件

必须全部满足：

- D2-T01至D2-T18通过；
- D0、D1回归无失败；
- 标定记录不可变、可校验、可追溯；
- 缺失、过期、非法、越界标定全部阻断；
- 稳态判据不依赖模拟状态标签；
- 同种子结果可重现；
- 故障场景进入预期质量状态；
- 删除派生结果后可以完整重建报告；
- API和Web手动验收通过；
- 验收报告记录测试数、运行命令、提交SHA和限制；
- 未把合成`au`写作真实力、压力或人体指标。

D2通过后进入D3自动施压与安全控制仿真，仍不购买硬件。

## 16. 明确不做

- 不购买传感器、ADC、MCU或电机；
- 不实现真实COM口和ESP32固件；
- 不确定人体载荷范围；
- 不训练脉象或疾病模型；
- 不把合成标定精度写进简历作为真实硬件精度；
- 不因D2通过而跳过D3直接采购。
