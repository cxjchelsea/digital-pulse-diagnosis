# 项目总体方案

## 1. 项目定位

项目正式定位为：

> **自适应桡动脉脉搏数字化采集与客观分析系统。**

系统目标不是制造一个只会显示波形的硬件设备，而是形成可解释、可验证的自适应采集方法，并保留从原始信号到工程报告和下一步采集决策的完整证据链。

项目主体输出：

- 数据完整性和信号质量；
- 心率、心搏间期和基础形态参数；
- 接触力与波形响应；
- 重戴、跨日和多人重复性；
- 接受、重采、调压、换位、停止和失败回退决策；
- 可追溯工程报告。

项目不默认输出脉象、证候、疾病或治疗结论。

## 2. 路线设计原则

项目发起人具备控制科学、机器学习、Python/Java/TypeScript、FastAPI、React、医疗AI系统和工业数据建模经验，嵌入式与电子硬件经验相对较少。因此路线遵循：

- 先利用软件和算法能力建立可测试闭环；
- 能在真实硬件前确定的接口、失败行为和软件结构尽量前置；
- 必须依赖真实器件和人体数据的问题不使用模拟结论替代；
- 优先使用开发板、成熟传感器和标准机械件；
- 每次采购对应一个模拟无法最终回答的问题；
- 用实验指标决定升级，不以组装完成作为成功；
- 保留原始、失败、处理、报告和决策数据；
- 不同时引入定制PCB、柔性材料、气动系统和复杂深度学习；
- 脉象研究不是项目主体完成条件。

## 3. 路线编号

### 3.1 D0–D3：数字基线

D0–D3已经完成并冻结：

- D0：基础合成采集、处理、分析和Web闭环；
- D1：设备通信、虚拟串口、握手、断连和重连；
- D2：标定、多压力实验、漂移/迟滞/削顶/伪影和自动报告；
- D3：自动施压被控对象、PID、安全状态机、故障、ABORT和卸载闭环。

D阶段只证明模型内的软件和控制行为成立，不能替代真实器件或人体证据。

### 3.2 M1–M6：系统能力里程碑

M编号是项目主线：

| 里程碑 | 核心能力 |
|---|---|
| M1 | 真实数据闭环 |
| M2 | 可信单点分析 |
| M3 | 压力响应与自适应采集 |
| M4 | 自动采集与安全编排 |
| M5 | 重复性与泛化验证 |
| M6 | 自动定位 |

项目进展由M里程碑判断，不由购买器件数量、机械复杂度或单独看到波形判断。

### 3.3 M1-P：真实接入前软件就绪

M1-P是M1内部的前置实施包，不是新的长期数字阶段。

M1-P在真实硬件接入前完成：

- M1正式数据契约和Schema；
- 多通道真实风格模拟器；
- SP-S1-pre信号处理预实现；
- APP-A1-pre分析软件预实现；
- INT-I1-pre规则决策预实现；
- 正常和失败场景的确定性验收。

M1-P不能完成真实噪声、漂移、迟滞、电气性能、人体阈值或真实重复性。

### 3.4 H1–H5：实体证据工作包

H编号只提供实体证据：

| 实体包 | 主要未知量 | 支持里程碑 |
|---|---|---|
| H1 | 单点传感器、ADC、MCU、探头和真实数据链路 | M1、M2 |
| H2 | 静态载荷、探头结构和多压力响应 | M3 |
| H3 | 自动施压机构和真实安全闭环 | M4 |
| H4 | 多人、跨日、重戴和操作者实验 | M5 |
| H5 | 多位置阵列或机械扫描 | M6 |
| H6 | 专业标签、伦理和外部研究 | 可选X1 |

H1–H5不再承担整个项目的阶段叙事。

## 4. 当前执行策略

当前系统里程碑为M1，采用：

```text
M1-P真实接入前软件就绪（主要实施）
＋ H1-A采购调研（并行）
```

默认顺序：

```text
M1-P数据契约
→ 多通道模拟器
→ SP/APP/INT预实现
→ M1-P模拟验收
→ M1-PV软件就绪验收
→ H1-A BOM与电气风险评审
→ 正式下单
→ H1-B到货与电气验收
→ H1-C真实数据接入
→ 真实参数校准和三条软件主线复验
→ H1手动单点与重戴
→ M1综合验收
```

H1-A调研与M1-P并行，不把等待硬件当作停止软件开发的理由。

默认下单门：

```text
M1-PV通过
＋ H1-A评审通过
＝ H1-ORDER正式下单
```

长交期器件提前购买必须形成工程决策记录。

## 5. 核心问题与研究假设

### 5.1 核心问题

在不同手腕尺寸、桡动脉位置、软组织厚度和佩戴状态下，怎样自动或半自动找到有效采集位置，并在已知接触力条件下获得稳定、重复的桡动脉脉搏波？

### 5.2 首期假设

1. 同步记录动态脉搏和静态接触力，比只记录单条波形更可解释；
2. 压力分层扫描能够找到个体化有效压力区间；
3. 信号质量评分能够减少无效数据进入后续分析；
4. 多位置采样能够降低人工定位依赖；
5. 规则和可解释统计应先于复杂模型；
6. 项目主体以客观参数、采集决策和重复性验证为终点。

这些是假设，不是结论，必须通过真实实验验证。

## 6. 三层数据链与决策平面

项目固定采用三层数据可信链，并增加一条跨层决策平面。

| 主线 | 核心问题 | 输入 | 输出 | 成功标准 |
|---|---|---|---|---|
| DAQ采集与执行 | 如何获得稳定、可校准的输入 | 手腕、探头、载荷、设备配置 | 原始ADC、载荷、PPG、状态和事件 | 数据完整、可校准、可重复 |
| SP信号处理 | 原始数据能否相信 | 原始帧、校准和状态 | 质量、标准波形、逐搏和特征 | 能识别噪声、失真和无效测量 |
| APP分析软件 | 如何形成可追溯结果 | 可信信号、特征和元数据 | 参数、对比、报告和失败解释 | 结果可解释、可重放、可追溯 |
| INT自适应决策 | 下一步怎样采集 | 安全、完整性、质量和历史结果 | 接受、重采、调压、换位或停止 | 决策保守、确定、可审计 |

```mermaid
flowchart LR
    A["DAQ<br/>模拟或真实采集"] --> B["SP<br/>完整性、质量、逐搏"]
    B --> C["APP<br/>会话、参数、报告"]
    C --> D["INT<br/>接受、重采、调压、换位、停止"]
    D --> A
```

INT不能覆盖设备侧安全状态机、急停和人工停止。

## 7. 数据契约

硬件不只输出一列脉搏幅值，最小样本应包含：

```text
帧序号
＋ 设备时间戳
＋ 动态脉搏原始值
＋ 静态载荷原始值
＋ 参考PPG
＋ 目标载荷/电机位置（可空）
＋ 设备状态
＋ 故障和通道有效性标志
＋ 版本引用
```

模拟器和真实硬件数据源必须遵循同一正式契约。真实接入后主要新增数据源适配器和参数校准，不重新设计整套SP、APP和INT接口。

数据分层：

- L0：原始帧和设备事件，不可覆盖；
- L1：工程单位数据；
- L2：质量掩码、处理波形和逐搏片段；
- L3：客观特征和模型输入；
- L4：决策、模型输出和人工标注。

每个派生层记录输入ID、代码SHA、配置、参数和生成时间。

## 9. MVP范围

### 9.1 必须实现

- 桌面式手腕托架和可更换单探头；
- 手动粗定位关部；
- 动态脉搏与静态接触力同步采样；
- 参考PPG同步；
- 原始数据不丢失地进入电脑；
- 实时显示波形、载荷、PPG、质量和设备状态；
- 基线处理、逐搏、心率和质量评分；
- 会话、原始、处理、决策和报告可追溯；
- 质量失败阻断参数并触发重采或停止；
- 后续自动多压力流程和设备侧安全状态机；
- 重复采集与参考心率对比实验。

### 9.2 明确不做

- 第一版不覆盖六部寸关尺；
- 不自研柔性传感材料；
- 不直接制作可穿戴腕带；
- 不使用LLM直接处理原始波形或控制硬件；
- 不输出疾病诊断和治疗建议；
- 不用单个受试者随机窗口切分宣称高准确率；
- 不在采集可靠性未知时训练复杂深度模型；
- 不把厂家宣传参数当作项目实测性能。

## 10. 算法策略

优先顺序：

1. 数据完整性硬门；
2. 明确安全和停止规则；
3. 可解释质量规则；
4. 心搏检测、形态和压力响应统计；
5. Logistic Regression、决策树等简单模型；
6. Random Forest/XGBoost；
7. 真实数据充分后再评估1D-CNN、TCN或Transformer。

模型要求：

- 按受试者拆分；
- 报告简单基线；
- 输出概率和不确定性；
- 保留独立测试集；
- 报告年龄、性别、腕围、设备和操作者等适用边界；
- 不使用LLM直接生成测量或诊断结果。

## 11. 硬件策略

### MCU

首版使用ESP32-S3开发板：成本低、资料多、USB方便，足以承担首期数百Hz多通道采样和状态控制。只有出现明确的实时性、接口、功耗或安全瓶颈后再评估STM32。

### 动态与静态分通道

动态脉搏和静态接触力优先分通道，避免大静载荷淹没动态信号。

### 执行机构

自动施压在M4/H3才进入实物闭环。首版使用电机＋丝杆桌面机构，便于限位、调试和更换探头；不提前引入气囊、泵阀和可穿戴复杂度。

### 采购原则

- 每项采购对应真实未知量；
- 首批保持最小数量；
- 必须核对模块原理图和版本；
- 不因已经购买而降低淘汰标准；
- 采购调研与M1-P并行；
- 默认M1-PV后下单。

## 12. 验证策略

### M1-P

验证软件行为：

- 正常；
- 无接触和弱信号；
- 削顶；
- 基线漂移和运动伪影；
- 接触力不稳；
- PPG错位；
- 丢帧和时间戳异常；
- 落盘失败；
- 重采改善和达到重采上限；
- ABORT和设备故障。

### H1/M1真实验证

验证真实问题：

- ADC零噪声和有效分辨率；
- 传感器漂移、迟滞和批次差异；
- 模拟前端和输入保护；
- 仿体重复响应；
- 真实PPG时延；
- 手动单点30–60秒波形；
- 至少3次完整重戴；
- 真实质量阈值和心率误差；
- 失败数据和停止路径。

M1-P黄金场景在真实接入后继续作为回归测试，不被删除。

## 13. 初始工程目标

以下目标必须在真实数据后冻结，不是当前已实现结果：

| 指标 | 初始目标 | 冻结阶段 |
|---|---:|---|
| 原始采样率 | 250–500 Hz | H1 |
| 连续采集丢帧率 | <0.1% | H1 |
| 心率MAE | ≤2 bpm | M1/M2 |
| 压力平台稳态误差 | ≤目标值5% | M4 |
| 压力超调 | ≤10% | M4 |
| 自动释放时间 | ≤2 s | M4 |
| 有效信号获取率 | ≥90% | M5前重新评审 |
| 同次重测关键特征CV | ≤15% | M5 |
| 自动寻脉成功率 | ≥85% | M6 |

若实测显示目标不合理，应通过工程决策记录调整，不能事后选择性报告。

## 14. 风险与应对

| 风险 | 后果 | 应对 |
|---|---|---|
| 过早进入采购等待 | 软件停滞、硬件到货后从零开发 | 先实施M1-P，H1-A并行 |
| 过度模拟 | 模拟器复杂但无法增加真实证据 | M1-P限定接口、失败行为和验收，不模拟未知真实性能 |
| 传感器漂移/迟滞 | 压力响应不可重复 | 多型号对照、标定、预热和温漂记录 |
| 电机振动污染 | 自动采集波形失真 | 到位停机、稳定窗口和隔振 |
| 定位差异 | 重测差 | 托架、位置记录和后续扫描 |
| 数据泄漏 | 模型指标虚高 | 受试者级拆分和冻结测试集 |
| 标签不一致 | 外部模型学习主观偏差 | H6才进行多专家和一致性研究 |
| 过早医疗宣称 | 安全和合规风险 | 限定工程原型和客观参数 |
| 范围过大 | 长期不能交付 | M里程碑、阶段门和非目标 |
