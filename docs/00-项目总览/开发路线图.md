# 开发路线图

时间是建议范围，不是承诺。项目采用“数字原型D线＋实体验证H线”：数字阶段先消除软件和控制逻辑风险，实体阶段用硬件和真实数据验证模型假设。

- D1：已完成并验收；
- D2：已完成并验收；

- H1：尚未正式启动，待D3收尾PR合并、main CI通过、正式验收证据生成及版本标记完成后进入。

## 路线原则

- D阶段可以用模拟数据验收软件行为，但不能替代H阶段；
- 只有前一阶段的接口和安全基线稳定后才进入下一阶段；
- D1–D3正式冻结后采购最小H1硬件包；
- H1之后数字开发与硬件实验交替推进，不再长期闭门生成模拟数据；
- 任何模拟指标不得写成真实设备或医学指标。

## D0：基础合成闭环（已完成）

交付：协议v0、确定性脉搏模拟器、原始落盘、重放、质量门控、FastAPI、React和自动测试。

阶段门：30分钟450000帧连续运行、丢帧0、CRC错误0、浏览器手动闭环通过。

## D1：设备通信数字原型（已完成）

交付：

- 固件行为模拟器；
- 设备传输抽象与虚拟串口；
- 握手、能力查询、命令与ACK/NACK；
- 断连、重连、粘包、分片和不完整会话；
- Web设备状态与错误提示。

阶段门：虚拟设备端到端、故障和重连测试全部通过。

## D2：标定与多压力数字实验（已完成）

交付：

- 版本化标定模型；
- 多压力profile和稳定窗口；
- 漂移、迟滞、削顶与运动伪影；
- 压力响应、质量门控和自动实验报告；
- 候选评分工具。

阶段门：正常和异常标定场景可重现，质量失败正式阻断。

## D3：自动施压与安全控制数字仿真（收尾强化中）

交付：

- 执行器—软组织简化模型；
- 压力PID控制器、限速、抗积分饱和和稳态判据；
- 设备侧安全监督器和状态机；
- 14类故障检测、优先级与确定性回归；
- ABORT、主机失联、硬超限和传感器失效的完整卸载闭环；
- 急停、电机卡滞和看门狗的零输出锁存；
- 正常多目标Profile；
- 可中止运行会话API；
- Web正常Profile控制和真实ABORT；
- 1800秒完整D3链路模型时间测试；
- D3-T01至D3-T24追踪；
- 可复现验收证据生成器；
- GitHub Actions Python和Web门禁。

阶段门：

- 正常多目标Profile满足冻结模型阈值；
- 14类故障检测和冻结优先级回归通过；
- 可退回故障完成卸载，超时不得误标成功；
- 锁存故障立即零输出并保持FAULT_LATCHED；
- ABORT API/Web到设备侧状态机闭环通过；
- 1800秒完整D3链路回归通过；
- D3-T01至D3-T24具有具体测试节点证据；
- Python、unittest、Web和GitHub Actions门禁通过；
- 正式验收报告记录代码SHA、完整配置、配置哈希和证据边界；
- 所有真实硬件未知量进入H1。

## H1：真实手动单点采集（待D3正式冻结后启动）

采购与实现：

- ESP32-S3、ADS1220、动态传感候选；
- 小量程称重传感器与NAU7802；
- USB传输、手动探头与参考PPG；
- 台架、仿体和低风险渐进腕部采集。

阶段门：真实脉搏连续30–60秒清晰可辨，无持续削顶，重戴至少3次并报告失败。

## H2：接触力与结构优化

实现：载荷标定、三种探头、手动多压力、真实压力响应和质量规则v1。

阶段门：载荷重复性和同人压力响应趋势达到冻结标准，确定传感器、ADC和探头组合。

## H3：自动施压实物闭环

实现：电机、丝杆、限位、急停、压力闭环和设备侧安全状态机。

阶段门：仿体安全回归通过；渐进人体测试前重新冻结载荷与停止条件。

## H4：多人重复性验证

实现：健康成人工程验证、跨日、重戴、不同操作者、质量模型和完整报告。

阶段门：有效率、心率误差和重复性有真实量化；此时项目才足以作为软硬件系统核心简历项目。

## H5：自动寻脉

实现：阵列或机械扫描A/B、空间质量图、自动选点和失败回退。

阶段门：真实测试中相对人工定位有明确收益，成本与可靠性可接受。

## H6：可选外部脉象研究

H6不属于项目主体完成条件。缺少中医师、伦理或可靠标注时保持暂停，不使用开源资料生成伪专家标签。

仅在固定硬件、固定协议、伦理隐私、至少两名合格中医师、标签手册和受试者级划分全部具备后启动。可提前完成标签Schema、标注工具和一致性统计，但不得输出脉象识别或诊断结论。
