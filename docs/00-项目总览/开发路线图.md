# 开发路线图

时间范围仅用于排序，不是交付承诺。

本项目从本版本开始使用两套彼此正交的编号：

- **M1–M6：系统能力里程碑**，决定项目整体处于什么阶段，是对外叙述和阶段验收的主线；
- **H1–H5：实体证据工作包**，负责提供传感器、结构、执行器和真实实验数据，不再单独代表整个项目阶段；
- **D0–D3：购买前数字基线**，已经完成并冻结，为后续真实系统提供协议、标定、控制、安全和测试基础；
- **H6：可选外部研究**，依赖专业人员、伦理和可靠标签，不属于项目主体完成条件。

项目的核心不是持续增加硬件，而是形成以下闭环：

```text
真实采集
→ 数据完整性与信号质量判断
→ 客观参数和实验分析
→ 生成接受、重采、调压、换位或停止决策
→ 再次采集并保留完整证据
```

## 2. 系统结构：三层数据链＋一条决策主线

项目仍采用“采集硬件—信号处理—分析软件”三层数据可信链，同时增加跨层的自适应采集决策主线。

| 主线 | 职责 | 核心输出 |
|---|---|---|
| **DAQ：采集与执行** | 传感器、ADC、MCU、探头、接触力、执行器和真实数据链路 | 可校准、可追溯的原始数据与设备状态 |
| **SP：信号处理** | 完整性、校准、稳态窗口、质量、滤波、逐搏、特征和空间质量 | 可信波形、质量标签、逐搏片段和客观特征 |
| **APP：分析软件** | 会话、存储、重放、可视化、参数、实验对比、版本追踪和报告 | 可复现、可解释、可追溯的分析结果 |
| **INT：自适应采集决策** | 根据安全、完整性、质量和历史结果决定下一步采集动作 | 接受、重采、调压、换位、停止和失败回退决策 |

四条主线不是平均分配工作量，而是在不同里程碑中轮流成为主要未知量。任何里程碑都必须至少形成“真实输入—可信处理—软件结果—下一步决策”的闭环。

## 4. 系统能力里程碑

## M1：真实数据闭环（当前阶段）

目标：真实脉搏数据能够进入系统，被完整保存、重放、初步质控和分析；系统能够根据质量结果做出接受或重采决定。

| 主线 | M1交付 |
|---|---|
| DAQ | H1真实单点采集证据包：ESP32-S3、候选传感器、ADC、静态载荷、USB、手动探头和参考PPG |
| SP | S1：真实帧完整性、单位换算、基础滤波、逐搏、削顶/断线/伪影规则和PPG对齐 |
| APP | A1：真实会话、原始数据优先落盘、完整重放、实时脉搏/载荷/PPG显示和基础参数 |
| INT | I1：质量通过则接受；质量不足时同位重采、提示换位或停止，并记录决策依据 |

综合阶段门：

- 真实数据连续进入正式协议和会话存储，CRC、序号和时间戳问题可追踪；
- 原始数据可完整重放，同一版本输入得到一致结果；
- 真实单点波形连续30–60秒，无持续削顶；
- 心搏与参考PPG可以量化对齐；
- 质量失败会阻断正式参数，并产生明确的重采或停止建议；
- 完全重戴至少3次，成功与失败数据都保留；
- 仅接通硬件、仅看到波形、仅完成算法或仅完成界面都不能通过M1。

## M2：可信单点分析

目标：系统能够解释一段真实单点数据为什么可信或不可信，并输出可追溯的客观参数。

| 主线 | M2交付 |
|---|---|
| DAQ | 冻结单点传感器、ADC、探头和基本采集条件，减少硬件变量 |
| SP | S1正式冻结：稳定窗口、质量原因、逐搏和基础形态特征经过真实数据复验 |
| APP | A2：心率、心搏间期、幅值、上升时间、波宽、面积、质量解释与参考对照报告 |
| INT | I1正式冻结：接受、重采、换位和停止规则具有可回放证据 |

阶段门：独立保留数据上，质量判断、心搏检测、参考心率误差和重戴结果达到预先冻结标准；每个参数均可追溯到原始数据、算法版本和参数配置。

## M3：压力响应与自适应采集

目标：系统能够分析不同接触力下的波形变化，并推荐个体有效压力区间和下一步采集动作。

| 主线 | M3交付 |
|---|---|
| DAQ | H2：载荷标定、探头结构比较和手动多压力真实采集 |
| SP | S2：稳态窗口、压力切换掩码、漂移/迟滞处理和压力响应特征 |
| APP | A3：压力—质量、压力—幅值、压力—形态曲线，候选比较和自动实验报告 |
| INT | I2：下一压力推荐、无收益停止、异常回退和最佳有效区间决策 |

阶段门：同一人在重复实验中形成可解释的压力响应趋势；系统的压力推荐优于固定盲扫基线，失败时能够停止而非强行输出结果。

## M4：自动采集与安全编排

目标：在真实安全约束下自动执行压力采集流程，并由实时质量反馈调整采集策略。

| 主线 | M4交付 |
|---|---|
| DAQ | H3：电机、丝杆、限位、急停、载荷闭环和设备侧安全状态机 |
| SP | S3：实时因果滤波、运动/换挡区间排除、状态对齐和无效数据阻断 |
| APP | A3增强：自动实验编排、状态时间线、ABORT、失败会话和完整重放 |
| INT | I3：继续、保持、换挡、重采、释放、停止和故障回退决策 |

阶段门：仿体安全回归、控制链路、信号处理和实验编排同时通过；控制目标达到但信号无效时不得把实验判为成功。

## M5：重复性与泛化验证

目标：证明系统能力在重戴、跨日、不同操作者和多人条件下是否成立，并诚实暴露适用范围。

| 主线 | M5交付 |
|---|---|
| DAQ | H4：冻结硬件、协议、探头和实验流程，执行多人/跨日/重戴实验 |
| SP | S4：质量模型、特征稳定性、漂移监测和不确定性 |
| APP | A4：重复性统计、亚组分析、失败模式、版本追踪和工程验证报告 |
| INT | I4：低置信度、分布外、冲突结果和人工复核触发 |

阶段门：有效率、心率误差、重戴与跨日重复性、失败率和适用边界均有真实量化；模型评估按受试者划分。

## M6：自动定位

目标：根据多位置真实数据自动选择更优采集点，并在失败时继续搜索或回退人工定位。

| 主线 | M6交付 |
|---|---|
| DAQ | H5：阵列或机械扫描A/B、多位置同步采集和位置标定 |
| SP | S5：空间质量图、位置间波形比较、空间伪影和一致性处理 |
| APP | A5：位置对比、自动选点评估、人工定位对照和实验报告 |
| INT | I5：选点、继续搜索、置信度、停止和失败回退 |

阶段门：真实测试中自动定位相对人工定位有明确收益，成本、时间和失败率可接受；无法确定时必须回退而非伪造确定性。

## 7. 路线原则

- 项目进展由M里程碑判断，不由购买器件数量或机械复杂度判断；
- 硬件是获得真实证据的载体，不是项目的唯一成果；
- 信号质量未通过时，APP不得输出正式客观参数；
- INT的决策必须可解释、可回放并受安全状态机约束；
- 首版INT优先采用明确规则、状态机和可解释统计，不为“智能”而引入复杂模型；
- H1之后真实实验、信号处理、软件和决策迭代交替推进；
- 任何模拟指标不得写成真实设备、人体或医学指标；
- 原始数据、失败数据、处理版本和决策记录均必须保留；
- 任何一条主线版本变化，相关验收必须标注适用版本并按需重跑。
