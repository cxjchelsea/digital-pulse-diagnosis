# 开发路线图

时间是建议范围，不是承诺。项目采用“数字原型D线＋实体验证H线”，并在每个实体阶段同时推进三条系统主线：

- **HW：采集硬件**——传感、模拟前端、ADC、MCU、机械与安全；
- **SP：信号处理**——完整性、校准、质控、滤波、逐搏、特征与压力响应；
- **APP：分析软件**——会话、存储、实时界面、客观参数、重复性分析与报告。

H阶段不是单纯的硬件路线。每一阶段都必须形成“真实采集 → 可信处理 → 可追溯分析”的闭环，不能只以器件接通或波形看起来清晰作为完成标准。

## 路线原则

- D阶段可以用模拟数据验收软件行为，但不能替代H阶段；
- 只有前一阶段的接口和安全基线稳定后才进入下一阶段；
- D1–D3正式冻结后采购最小H1硬件包；
- H1之后硬件实验、信号处理和分析软件交替推进，不再长期闭门生成模拟数据；
- 每个H阶段必须同时列出HW、SP、APP交付物和综合阶段门；
- 原始数据永久保留，任何校准、滤波、切分、特征和模型输出均生成新版本并记录代码、参数与输入数据；
- 信号质量未通过时，分析软件必须拒绝生成正式结果并提示重采；
- 任何模拟指标不得写成真实设备、人体安全或医学指标。

阶段门：30分钟450000帧连续运行、丢帧0、CRC错误0、浏览器手动闭环通过。

## H1：真实手动单点采集（H1-A启动）

| 主线 | H1交付 |
|---|---|
| **HW-H1** | ESP32-S3、动态传感候选、ADS1220、小量程称重传感器、NAU7802、USB、手动探头、参考PPG、仿体和低风险渐进腕部采集 |
| **SP-S1** | 真实帧完整性、ADC计数与工程单位版本、零噪声/削顶/断线检测、基础实时与离线滤波、初版逐搏检测、质量规则v0、PPG时序对齐 |
| **APP-A1** | 真实设备会话、硬件/固件/校准版本管理、原始数据优先落盘、完整重放、实时脉搏/载荷/PPG显示、质量失败原因、H1实验报告 |

综合阶段门：

- 真实单点波形连续30–60秒稳定且无持续削顶；
- CRC、序号、时间戳、断线和不完整会话可追踪；
- 与参考PPG的逐搏匹配和心率误差有量化结果；
- 信号质量不足时APP不得输出正式参数；
- 完全拆装重戴至少3次，并同时保存成功与失败样本；
- 给出传感器、ADC、探头的推荐、备选和淘汰理由。

## H5：自动寻脉

| 主线 | H5交付 |
|---|---|
| **HW-H5** | 阵列或机械扫描A/B、多位置同步采集和位置坐标基线 |
| **SP-S5** | 空间信号质量图、位置间波形比较、空间伪影识别、局部一致性和选点输入特征 |
| **APP-A5** | 自动选点、置信度、失败回退、人工定位对照、A/B评估和可解释决策记录 |

综合阶段门：自动定位相对人工定位在有效率、时间或重复性上有明确收益，成本与可靠性可接受，失败能够识别并安全回退。

## H6：可选外部脉象研究

H6不属于项目主体完成条件。缺少中医师、伦理或可靠标注时保持暂停，不使用开源资料生成伪专家标签。

仅在固定硬件、固定协议、伦理隐私、至少两名合格中医师、标签手册和受试者级划分全部具备后启动。可提前完成标签Schema、标注工具和一致性统计，但不得输出脉象识别或诊断结论。
