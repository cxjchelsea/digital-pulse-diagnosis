# 开发路线图

时间范围仅用于排序，不是交付承诺。

本项目使用三套彼此正交的编号：

- **M1–M6：系统能力里程碑**，决定项目整体处于什么阶段，是对外叙述和正式验收的主线；
- **M1-P：M1真实接入前软件就绪工作包**，在正式硬件接入前完成数据契约、模拟器、信号处理、分析软件、自适应决策和确定性验收；
- **H1–H5：实体证据工作包**，负责提供传感器、结构、执行器和真实实验数据，不再单独代表整个项目阶段；
- **D0–D3：购买前数字基线**，已经完成并冻结，为后续真实系统提供协议、标定、控制、安全和测试基础；
- **H6：可选外部研究**，依赖专业人员、伦理和可靠标签，不属于项目主体完成条件。

M1-P不是新的长期闭门仿真阶段，也不能替代真实验证。它只负责把真实硬件接入前能够确定的软件结构、接口、失败行为和验收门提前实现完整。

项目核心闭环为：

```text
采集
→ 数据完整性与信号质量判断
→ 客观参数和实验分析
→ 生成接受、重采、调压、换位或停止决策
→ 再次采集并保留完整证据
```

## 2. 系统结构：三层数据链＋一条决策主线

| 主线 | 职责 | 核心输出 |
|---|---|---|
| **DAQ：采集与执行** | 传感器、ADC、MCU、探头、接触力、执行器、模拟数据源和真实数据链路 | 可校准、可追溯的原始数据与设备状态 |
| **SP：信号处理** | 完整性、校准、稳态窗口、质量、滤波、逐搏、特征和空间质量 | 可信波形、质量标签、逐搏片段和客观特征 |
| **APP：分析软件** | 会话、存储、重放、可视化、参数、实验对比、版本追踪和报告 | 可复现、可解释、可追溯的分析结果 |
| **INT：自适应采集决策** | 根据安全、完整性、质量和历史结果决定下一步采集动作 | 接受、重采、调压、换位、停止和失败回退决策 |

模拟数据源和未来真实数据源必须使用同一正式接口。真实接入后允许校准参数和替换数据源，不允许为适配硬件重新设计整套会话、质量、报告和决策结构。

## 3. M1-P：真实接入前软件就绪

### 3.1 定位

M1-P回答：

> 在没有真实硬件的前提下，是否已经把将来接入真实数据所需的软件结构、数据契约、异常场景、质量阻断和决策闭环实现到可替换数据源的程度？

M1-P可以完成：

- 输入输出契约和机器可读Schema；
- 多通道真实风格模拟数据；
- SP-S1的算法结构、原因代码、版本追踪和测试；
- APP-A1的会话、存储、重放、界面、报告和阻断逻辑；
- INT-I1的规则、状态、重采上限、人工复核和审计记录；
- 正常与失败场景的确定性回归。

M1-P不能完成：

- 真实传感器噪声、漂移和迟滞；
- ADC有效分辨率和真实采样抖动；
- 探头与皮肤耦合；
- 真实运动伪影分布；
- PPG与脉搏通道真实时延；
- 真实质量阈值、滤波参数和人体有效率；
- H1或M1正式验收。

### 3.2 工作包

| ID | 工作包 | 主要输出 |
|---|---|---|
| M1-P0 | 数据契约与Schema | 样本、会话、质量、决策、报告和版本字段 |
| M1-P1 | 多通道真实风格模拟器 | 脉搏、载荷、PPG、状态、事件和故障场景 |
| M1-P2 | SP-S1-pre | 完整性、稳定窗口、滤波、逐搏、质量和PPG对齐预实现 |
| M1-P3 | APP-A1-pre | 会话、落盘、重放、实时展示、基础参数、报告和失败状态 |
| M1-P4 | INT-I1-pre | 接受、重采、换位、人工复核、停止和安全释放决策 |
| M1-P5 | 模拟验收矩阵 | 正常、弱信号、削顶、丢帧、PPG冲突、重采和ABORT回归 |
| M1-PV | 软件就绪验收 | 接口统一、结果可重放、失败不可绕过、真实待校准项明确 |

跟踪入口：Issue #29。

### 3.3 M1-P退出条件

- 模拟数据源与真实数据源适配器遵循同一协议和Schema；
- 原始、处理、事件、报告和决策均可重放；
- 质量失败不能绕过并生成正式参数；
- 最大重采次数和停止条件有效，不能无限循环；
- 同一输入、代码、配置和规则版本得到一致结果；
- 所有依赖真实数据的阈值标记为`pending_h1_calibration`；
- CI覆盖M1-P核心单元、场景和Web构建；
- 验收报告明确：M1-P通过不等于H1或M1通过。

## 5. 系统能力里程碑

## M1：真实数据闭环（当前里程碑）

目标：真实脉搏数据能够进入系统，被完整保存、重放、初步质控和分析；系统能够根据质量结果做出接受或重采决定。

| 主线 | M1交付 |
|---|---|
| DAQ | H1真实单点采集证据包：ESP32-S3、传感器、ADC、静态载荷、USB、手动探头和参考PPG |
| SP | S1：真实帧完整性、单位换算、基础滤波、逐搏、质量规则和PPG对齐 |
| APP | A1：真实会话、原始数据优先落盘、完整重放、实时多通道显示和基础参数 |
| INT | I1：质量通过则接受；不足时同位重采、提示换位、人工复核或停止 |

综合阶段门：

- 真实数据连续进入正式协议和会话存储，CRC、序号和时间戳问题可追踪；
- 原始数据可完整重放，同一版本输入得到一致结果；
- 真实单点波形连续30–60秒，无持续削顶；
- 心搏与参考PPG可以量化对齐；
- 质量失败阻断正式参数，并产生明确决策；
- 完全重戴至少3次，成功与失败数据都保留；
- 仅M1-P通过、仅接通硬件、仅看到波形或仅完成界面都不能通过M1。

## M2：可信单点分析

目标：系统能够解释一段真实单点数据为什么可信或不可信，并输出可追溯的客观参数。

| 主线 | M2交付 |
|---|---|
| DAQ | 冻结单点传感器、ADC、探头和基本采集条件 |
| SP | S1正式冻结：稳定窗口、质量原因、逐搏和基础形态特征经过真实复验 |
| APP | A2：心率、心搏间期、幅值、上升时间、波宽、面积和参考对照报告 |
| INT | I1正式冻结：接受、重采、换位、复核和停止规则具有真实证据 |

阶段门：独立保留数据上，质量判断、心搏检测、参考心率误差和重戴结果达到预先冻结标准；每个参数均可追溯到原始数据、算法版本和配置。

## M3：压力响应与自适应采集

目标：分析不同接触力下的波形变化，推荐个体有效压力区间和下一步采集动作。

| 主线 | M3交付 |
|---|---|
| DAQ | H2：载荷标定、探头结构比较和手动多压力真实采集 |
| SP | S2：稳态窗口、压力切换掩码、漂移/迟滞处理和压力响应特征 |
| APP | A3：压力—质量、幅值、形态曲线，候选比较和自动报告 |
| INT | I2：下一压力推荐、无收益停止、异常回退和有效区间决策 |

阶段门：重复实验形成可解释压力响应趋势；推荐策略与固定盲扫基线比较，失败时能够停止。

## M4：自动采集与安全编排

目标：在真实安全约束下自动执行压力采集流程，并由实时质量反馈调整策略。

| 主线 | M4交付 |
|---|---|
| DAQ | H3：电机、丝杆、限位、急停、载荷闭环和设备侧安全状态机 |
| SP | S3：实时因果滤波、运动/换挡排除、状态对齐和无效数据阻断 |
| APP | A3增强：自动实验编排、状态时间线、ABORT和失败会话重放 |
| INT | I3：继续、保持、换挡、重采、释放、停止和故障回退 |

阶段门：仿体安全回归、控制链路、信号处理和实验编排同时通过；控制达到目标但信号无效时不得判实验成功。

## M5：重复性与泛化验证

目标：验证重戴、跨日、不同操作者和多人条件下的适用范围。

| 主线 | M5交付 |
|---|---|
| DAQ | H4：冻结硬件和流程，执行多人、跨日、重戴实验 |
| SP | S4：质量模型、特征稳定性、漂移监测和不确定性 |
| APP | A4：重复性统计、亚组分析、失败模式和工程验证报告 |
| INT | I4：低置信度、分布外、冲突结果和人工复核触发 |

阶段门：有效率、心率误差、重戴与跨日重复性、失败率和适用边界均有真实量化；模型按受试者划分。

## M6：自动定位

目标：根据多位置真实数据自动选择更优采集点，并在失败时继续搜索或回退人工定位。

| 主线 | M6交付 |
|---|---|
| DAQ | H5：阵列或机械扫描、多位置采集和位置标定 |
| SP | S5：空间质量图、位置间比较、空间伪影和一致性处理 |
| APP | A5：位置对比、自动选点评估和人工定位对照 |
| INT | I5：选点、继续搜索、置信度、停止和失败回退 |

阶段门：自动定位相对人工定位有明确收益，成本、时间和失败率可接受；无法确定时必须回退。

## 8. 路线原则

- 项目进展由M里程碑判断，不由购买数量或机械复杂度判断；
- M1-P优先完成可以确定的软件结构，但不得伪造真实阈值和性能；
- H1-A采购调研与M1-P并行，不把等待硬件作为停止软件开发的理由；
- 模拟数据源和真实数据源必须使用统一接口；
- 信号质量未通过时，APP不得输出正式参数；
- INT决策必须可解释、可回放并受安全状态机约束；
- 原始数据、失败数据、处理版本和决策记录必须保留；
- 任何模拟指标不得写成真实设备、人体或医学指标；
- 真实接入后必须重新校准阈值，并重跑M1正式验收。
