# M1-P1多通道真实风格模拟器实施方案

版本：0.4.0；状态：M1-P1A/P1B/P1C已实现；M1-P1D尚未开始。

## 1. 阶段定位

M1-P1是M1-P“真实接入前软件就绪”中的第二个工作包，建立后续SP-S1-pre、APP-A1-pre、INT-I1-pre和M1-P5端到端验收共同使用的统一模拟数据源。

M1-P1直接建立在M1-P0已冻结的数据契约之上：

- `M1Sample`
- `M1Session`
- `M1QualityResult`
- `M1Decision`
- `M1Report`
- `protocols/m1-*.schema.json`

本阶段目标是：

> 用同一确定性心搏时间轴生成Pulse、Load和PPG多通道观测，能够按集中注册的场景注入信号、设备、传输和会话故障，并将结果按M1正式契约保存、验证和重放。

M1-P1通过只表示模拟数据源与故障证据可供后续软件开发使用：

- M1-P1通过 ≠ M1-P通过；
- M1-P1通过 ≠ H1通过；
- M1-P1通过 ≠ M1通过；
- 模拟结果不得写成真实传感器、人体或医学性能。

跟踪Issue：#29。

## 2. 与相邻工作包的边界

| 工作包 | M1-P1提供 | M1-P1不负责 |
|---|---|---|
| M1-P0 | 复用正式契约、Schema和兼容适配 | 不静默修改字段语义或Schema版本 |
| M1-P2 | 多通道输入、故障时间线、预期质量标签与原因 | 不实现正式滤波、逐搏和质量分类算法 |
| M1-P3 | 会话目录、原始样本、事件、重放数据源 | 不实现正式Web分析页面和业务报告 |
| M1-P4 | 多attempt场景、设备状态、预期动作 | 不实现INT规则引擎或自动执行重采 |
| M1-P5 | 可重复场景、黄金摘要、失败证据 | 不替代端到端质量、软件和决策验收 |
| H1-C | 定义未来真实数据源必须实现的接口 | 不实现ESP32、ADC、串口或真实硬件适配 |

模拟器与未来真实硬件只允许在DAQ适配层不同：

```text
SimulatorDataSource ─┐
ReplayDataSource ────┼→ Iterator[M1Sample] → SP → APP → INT
HardwareDataSource ──┘
```

SP、APP和INT不得依赖模拟器内部类、随机数生成器或场景实现。

## 3. 可验证与不可验证边界

### 3.1 M1-P1可以验证

- M1-P0契约可用于持续多通道数据；
- 帧序号、设备时间和主机时间语义；
- Pulse、Load、PPG共享统一采样和心搏基准；
- 正常、信号异常、设备异常、传输异常和会话异常的结构化表达；
- 同一配置和种子生成相同结果；
- 会话、事件、场景、预期结果的保存与重放；
- 模拟数据源和未来硬件数据源的公共接口；
- 后续质量阻断和决策规则所需的测试输入是否充分。

### 3.2 M1-P1不能验证

- 真实传感器噪声、漂移、迟滞和批次差异；
- ADC有效分辨率、参考源误差和采样抖动；
- 压电保护、模拟前端和实际电气安全；
- 探头与皮肤耦合；
- 真实运动伪影分布；
- PPG与脉搏通道真实时延；
- 真实质量阈值、滤波参数、重采次数和人体有效率；
- 真实安全载荷；
- 医学诊断、脉象、疾病或治疗结论。

所有依赖真实数据的参数保持`pending_h1_calibration`。

## 4. 总体架构

```text
ScenarioDefinition
→ ScenarioConfig
→ DeterministicClock
→ BeatTimeline
→ ChannelModels(Pulse/Load/PPG)
→ FaultInjector
→ DeviceStateModel
→ M1Sample
→ SessionRecorder
→ ReplayDataSource
```

核心职责：

| 组件 | 职责 | 禁止承担 |
|---|---|---|
| ScenarioDefinition | 注册场景ID、默认参数、故障计划和预期结果 | 不执行质量算法 |
| ScenarioConfig | 解析覆盖参数并生成配置摘要 | 不读取外部硬件状态 |
| DeterministicClock | 生成序号、设备时间、相对时间和确定性UTC | 不依赖真实系统时钟推进 |
| BeatTimeline | 生成统一心搏事件 | 不生成通道噪声 |
| ChannelModels | 将事件映射为Pulse、Load、PPG观测 | 不决定质量标签 |
| FaultInjector | 按层次和区间修改观测、状态或传输 | 不隐藏故障来源 |
| DeviceStateModel | 生成设备状态、传感器状态和故障标志 | 不实现INT动作决策 |
| SessionRecorder | 写入正式会话文件并生成摘要 | 不重算随机波形 |
| ReplayDataSource | 从保存结果恢复M1Sample | 不重新运行模拟器 |

详细设计见《M1多通道模拟器架构设计》。

## 6. 确定性策略

确定性键：

```text
scenario_id
+ scenario_version
+ random_seed
+ simulator_version
+ configuration_digest
```

同一确定性键必须生成相同的：

- 样本数量和顺序；
- `frame_sequence`；
- `device_time_us`；
- Pulse、Load、PPG值；
- 通道状态和削顶标志；
- 设备状态和故障标志；
- 事件顺序；
- 会话摘要；
- `expected.json`；
- 黄金摘要哈希。

UTC时间使用配置中的冻结起点加相对时间生成，不直接读取运行时当前时间作为数据内容。

不同随机种子可以改变噪声细节，但不能改变场景核心语义。例如`weak_signal`在所有允许种子下仍必须满足弱信号生成约束。

## 7. 正式输出

首版会话目录：

```text
session-id/
├── manifest.json
├── samples.jsonl
├── events.jsonl
├── scenario.json
├── expected.json
├── summary.json
└── raw_frames.bin        # 仅显式启用旧协议兼容验证时生成
```

文件职责：

| 文件 | 职责 |
|---|---|
| `manifest.json` | M1Session契约、文件角色、来源、版本和完整性摘要 |
| `samples.jsonl` | 每行一个通过M1 Sample Schema的对象 |
| `events.jsonl` | 会话生命周期、故障开始/结束、设备状态变化和写入错误 |
| `scenario.json` | 场景定义、覆盖参数、种子、版本和配置摘要 |
| `expected.json` | 后续SP/INT应验证的预期，不代表已执行算法 |
| `summary.json` | 小型黄金摘要、计数、统计和内容哈希 |
| `raw_frames.bin` | 可选旧协议兼容证据，不是默认主存储 |

首版选择JSONL作为样本输出，原因：

- 与JSON Schema直接对应；
- 无需新增Parquet依赖；
- 易于逐行验证和失败恢复；
- M1-P1规模可控；
- 后续APP阶段可在不改变M1Sample语义的前提下增加Parquet派生层。

所有文件引用使用相对路径，不写入本机绝对路径。

## 8. 实施分解

## M1-P1A：架构与基础多通道（已完成）

实际代码结构：

```text
src/digital_pulse/m1_simulator/
├── __init__.py
├── config.py
├── clock.py
├── timeline.py
├── channels.py
├── datasource.py
└── scenarios.py
```

已交付：

- `M1DataSource`公共协议与`SimulatorDataSource`；
- `ScenarioConfig`、`configuration_digest`与P1A场景注册表；
- `DeterministicClock`：`sample_count = round(duration_s * sample_rate_hz)`，`device_time_us = round(index * 1e6 / sample_rate_hz)`；
- `BeatTimeline`与独立RNG流（beat/pulse/load/ppg）；
- Pulse、Load、PPG基础观测通道；
- `normal_high_quality`；
- M1Sample逐条运行时与Schema验证；
- P1A自动化测试。

关键冻结规则：

- `samples()`每次调用都从同一配置重新确定性生成；
- 手动单点阶段`target_load_raw`与`motor_position_raw`为`null`；
- `parameter_status=pending_h1_calibration`；
- 不实现会话落盘、Replay、CLI或任何P1B/P1C故障。

退出门：同种子结果一致、不同种子仅改变允许细节、通道共享心搏、正常样本全部合法、D0–D3回归通过。

## M1-P1B：信号与接触异常（已完成）

实际代码增量：

```text
src/digital_pulse/m1_simulator/
├── scenario_ids.py          # 已实现场景ID集合（避免config↔scenarios循环）
├── faults.py                # FaultKind / FaultWindow / SignalFaultInjector
├── scenarios.py             # ScenarioDefinition + P1B注册表
└── （扩展）config / channels / timeline / datasource
```

已交付：

- `ScenarioDefinition`集中保存场景元数据与后续预期（不执行INT）；
- `FaultKind`、`FaultWindow`、默认窗口`[0.25·T, 0.75·T)`；
- `SignalFaultInjector`固定注入顺序：接触 → 幅值/基线 → 运动 → 削顶/clipping；
- 9个信号与接触场景：`weak_signal`、`no_contact`、`upper_saturation`、`lower_saturation`、`baseline_drift`、`motion_artifact`、`unstable_load`、`ppg_misalignment`、`insufficient_duration`；
- `no_contact`契约表达：传感器保持`connected`，Load近零接触区，Pulse无有效脉动；
- 合成削顶边界`synthetic_upper/lower_limit_raw`，数值与`clipping`一致；
- P1B兼容版本`0.2.0-p1b`；`normal_high_quality`默认仍用`0.1.0-p1a`；
- 空`fault_schedule`不进入canonical，避免正常场景摘要漂移；
- P1C前元数据修复：`normal`预期为`acceptable/accept`（`QualityLabel`/`DecisionAction`枚举）。

未交付（留给P1D）：

- `events.jsonl`正式落盘；
- `expected.json`会话产物；
- SessionRecorder、Replay、CLI。

退出门：数值、status、clipping一致；多seed语义稳定；normal无回归；D0–D3与CI通过。

## M1-P1C：设备、传输、存储和多attempt异常（已完成）

实际代码增量：

```text
src/digital_pulse/m1_simulator/
├── transport.py       # FrameLoss / TimestampRegression
├── device_faults.py   # sensor_disconnection / abort / device_fault
├── capture.py         # InMemory/Failing sink + CaptureRunner
├── attempts.py        # MultiAttemptPlan
├── events.py          # 内存 SimulationEvent（不写文件）
└── （扩展）config / datasource / scenarios / scenario_ids
```

分层顺序：

```text
BeatTimeline → 基础通道 → SignalFaultInjector → DeviceFaultController
→ 候选M1Sample → TransportFaultInjector → yield
→ CaptureRunner（仅 persistence 场景）
```

已交付：

- `frame_loss`：保留原始`frame_sequence`缺口；缺口后首样本`sequence_valid=false`；
- `timestamp_regression`：序号连续，指定帧`device_time_us`回退且`timestamp_valid=false`；
- `sensor_disconnection`：Pulse `disconnected+null`，`FAULT`+`sensor_disconnected`，之后停止；
- `abort`：`SAFE_HOLD`+`emergency_stop`后停止；
- `device_fault`：`FAULT`+Schema合法`buffer_overflow`后停止；
- `raw_persistence_failure`：内存`FailingSampleSink`，无磁盘破坏；
- `retry_improves` / `retry_still_fails`：固定`MultiAttemptPlan`，`get_scenario`拒绝并要求`get_attempt_plan`；
- 版本：`SIMULATOR_VERSION=0.3.0-p1c`；P1A/P1B兼容版本不变；空P1C计划字段从canonical省略。

未交付（P1D）：正式会话目录、Replay、CLI、JSONL/`expected.json`写入。

退出门：设备/传输/存储与信号异常可区分；终止场景固定帧结束；18案例可发现；D0–D3与CI通过。

## 10. 版本和配置

当前版本策略：

- 包级`SIMULATOR_VERSION`：`0.3.0-p1c`
- `P1B_COMPAT_SIMULATOR_VERSION`：`0.2.0-p1b`
- `normal_high_quality`默认`simulator_version`：`0.1.0-p1a`（P1A兼容）
- 场景版本：每个场景独立`1.0.0`
- M1 Schema：复用M1-P0冻结版本
- 参数状态：`pending_h1_calibration`

配置摘要使用规范化JSON计算SHA-256。摘要输入必须排除输出目录等与数据语义无关字段，并包含所有影响样本或事件的配置。

## 11. 方案评审门

进入代码实现前必须确认：

- 直接复用M1-P0契约，没有第二套公共样本类型；
- SP、APP、INT不依赖模拟器内部实现；
- 三通道共享BeatTimeline；
- 故障注入层次和顺序明确；
- 每个场景具有稳定ID、版本和预期；
- 所有随机过程受显式种子控制；
- 没有用模拟值冻结真实阈值；
- 会话失败仍保留可用证据；
- 输出格式不引入不必要依赖；
- 测试覆盖确定性、Schema、同步、故障、重放和回归。

发现M1-P0阻断性契约问题时停止实现，记录问题并评估Schema补丁版本，不静默修改。
