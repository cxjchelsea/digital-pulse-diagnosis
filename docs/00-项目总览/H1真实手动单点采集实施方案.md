# H1真实手动单点采集实施方案（原P1）

版本：0.6.0；状态：H1-A采购调研与M1-P并行执行，尚未进入强制下单阶段。

## 1. 定位

H1是M1“真实数据闭环”中的DAQ实体证据工作包，不是整个项目的主阶段。

H1回答：

> 真实传感器、ADC、MCU、探头和参考通道能否提供可校准、可追溯、可重复的单点原始数据？

H1不单独回答：

- 信号处理是否已经形成可靠质量规则；
- 客观参数是否已经通过参考对照；
- 软件是否已经能够完整重放和报告；
- 系统是否已经能够根据质量决定接受、重采、换位或停止。

因此：

- **H1通过不等于M1通过**；
- H1只提供M1需要的真实数据源和实体实验依据；
- M1还必须完成SP-S1、APP-A1、INT-I1和综合验收；
- 当前主要开发工作可以在M1-P中先推进，不需要等待硬件到货。

## 2. 当前执行关系

当前并行执行两类工作：

| 工作 | 负责人/入口 | 当前目标 |
|---|---|---|
| M1-P软件就绪 | Issue #29 | 数据契约、模拟器、SP/APP/INT预实现和模拟验收 |
| H1-A采购调研 | Issue #6 | 实际型号、供应商、价格、交期、原理图、验证假设和备选方案 |

H1-A当前允许完成调研和BOM评审准备，但不默认要求立即下单。

默认正式下单门：

```text
M1-PV真实接入前软件就绪验收通过
＋ H1-A采购与电气风险评审通过
＝ 可以正式下单
```

长交期或库存风险器件确需提前购买时，必须在《工程决策记录》中写明：

- 提前购买理由；
- 尚未冻结的软件或数据接口；
- 可能损失；
- 替代方案；
- 决策日期和责任人。

## 3. 与M1四条主线的关系

| 主线 | H1提供的输入 | M1-P和M1中其他工作包完成的能力 |
|---|---|---|
| DAQ | 真实传感器、ADC、MCU、静态载荷、探头、PPG和USB数据链路 | M1-P先冻结统一接口，H1真实适配器按接口接入 |
| SP | 原始帧、校准、设备状态、参考PPG和失败数据 | S1-pre先完成结构，S1再用真实数据校准和复验 |
| APP | 真实会话、硬件版本、原始文件和事件 | A1-pre先完成会话、重放和界面，A1再接入真实数据源 |
| INT | 质量标签、设备状态、重采历史和停止原因 | I1-pre先完成规则，I1再用真实结果校准触发条件 |

H1-C形成首批稳定台架数据后，应立即进入真实校准和复验，不需要等待H1全部机械和人体任务结束。

## 4. 前置条件

### 4.1 H1-A调研前置条件

- D1设备通信、正式协议、断连恢复和会话边界已冻结；
- D2标定、多压力、质量阻断和实验报告流程已冻结；
- D3控制状态机、安全故障矩阵和ABORT闭环已冻结；
- 每项候选采购对应一个模拟无法最终回答的问题；
- D0/D2中的相对载荷值不得转换为人体安全载荷。

### 4.2 正式下单前置条件

- M1-P正式数据契约已冻结；
- 真实硬件数据源适配器接口明确；
- M1-PV验收通过；
- 实际模块原理图、供电、电平和接口已审查；
- 候选、备选和淘汰条件明确；
- 采购价格、库存和交期具有查询日期；
- 到货和电气验收方法已准备。

### 4.3 人体测试前置条件

所有人体采集必须晚于：

- 到货电气验收；
- 压电输入保护和模拟前端台架验证；
- ADC零噪声、静态载荷标定和仿体重复脉动；
- 原始数据完整落盘和重放；
- SP质量失败识别；
- APP参数阻断；
- 明确的低风险停止条件。

## 5. H1范围

### 5.1 H1必须交付

- 带日期、来源、模块版本、原理图和备选方案的最小BOM；
- ESP32-S3真实采样和正式USB协议链路；
- 至少一个动态脉搏候选通道；
- 一个静态载荷通道；
- 一个参考PPG通道；
- 原始帧、事件、硬件版本和校准信息可追溯保存；
- 台架零噪声、漂移、迟滞、重复加载和仿体动态响应数据；
- 候选传感器、ADC和探头的推荐、备选与淘汰依据；
- 低风险手动单点数据和至少3次完整重戴记录；
- 成功与失败数据全部保留。

### 5.2 H1不完成

- M1-P软件就绪实现；
- SP-S1正式算法冻结；
- APP-A1完整软件验收；
- INT-I1正式决策验收；
- 自动施压；
- 压力响应自适应策略；
- 自动寻脉；
- 定制PCB和可穿戴结构；
- 脉象、疾病或治疗结论。

## 6. 候选架构

- 动态候选：TE LDT0-028K压电薄膜、Interlink FSR 402压阻薄膜；
- 主ADC：TI ADS1220；ADS1115仅作为快速接线或对照备选；
- 静态载荷：100 g与500 g级四线桥称重传感器＋NAU7802；
- 参考：MAX30102，仅用于心搏时序与心率参考；
- MCU：ESP32-S3-DevKitC-1；
- 传输：USB串口，复用D1冻结协议；
- 结构：台架、仿体、手腕托架和三种可替换探头。

候选名称不是最终采购结论。H1-A必须核对实际店铺中的完整料号、模块版本和原理图。

LDT0-028K必须经过限流、钳位和高输入阻抗缓冲后进入ADC，禁止直接连接MCU或ADC输入。

当前可以执行：

2. 记录实际供应商、商品链接、价格、运费、库存和交期；
3. 记录查询日期；
4. 记录官方数据手册版本；
5. 获取并审查开发模块原理图；
6. 核对供电、电平、接口、参考源和关键引脚；
7. 为每个器件写明要验证的假设；
8. 写明不通过时的替代方案；
9. 准备到货电气验收表；
10. 形成等待M1-PV后评审的冻结BOM。

当前不要求：

- 立即付款下单；
- 等待硬件期间停止软件开发；
- 在H1-A分支实现ESP32固件；
- 用厂家宣传参数作为项目实测结果；
- 把候选型号写成已验证硬件方案。

## 9. H1执行顺序

```text
H1-A采购调研（与M1-P并行）
→ M1-PV＋BOM评审
→ H1-ORDER正式下单
→ H1-B到货与电气验收
→ H1-C真实数据链路
→ H1-D传感器和探头证据
→ SP-S1 / APP-A1 / INT-I1真实校准与复验
→ H1-E手动单点与重戴
→ M1-V综合验收
```

具体步骤：

1. H1-A补齐动态采购信息；
2. M1-P冻结正式接口和软件预实现；
3. M1-PV和BOM评审通过后下单；
4. H1-B逐件完成电气验收；
5. ADC短接输入完成至少10分钟零噪声；
6. 压电保护与缓冲先在台架验证；
7. H1-C完成ESP32-S3、ADC、正式协议和原始落盘；
8. 首批台架数据稳定后立即进行SP/APP/INT真实复验；
9. H1-D完成FSR、压电、称重通道和探头比较；
10. 全部低风险门通过后才执行H1-E腕部采集；
11. 保存全部原始、失败、处理、报告和决策数据；
12. 执行M1-V综合验收。

## 10. 人体测试前硬性阶段门

- 全部使用低压供电；
- 无锐边、夹压和无法立即移除的结构；
- 压电输入保护通过；
- 模块供电、电平和接线经过复核；
- CRC、序号和时间戳连续性可追踪；
- ADC不持续削顶，断线和饱和可识别；
- 静态载荷完成砝码标定；
- 仿体重复脉动至少10次可复现；
- 原始数据可完整重放；
- 已冻结渐进载荷、停止条件和失败记录方法；
- 质量不足时软件能够阻断正式参数；
- INT不会无限重采，并保留人工停止权。

## 11. H1退出标准

H1退出只表示实体证据包可供M1使用：

- 实际BOM、来源、批次、接线和模块版本完整；
- 真实原始数据通过正式接口进入系统；
- 零噪声、漂移、迟滞、重复加载和仿体动态数据完整；
- 至少一个动态传感方案和一个静态载荷方案通过实体阶段门；
- 传感器、ADC和探头具有推荐、备选及淘汰理由；
- 形成30–60秒真实单点记录和至少3次重戴数据；
- 保存成功与失败样本；
- 固件、接线、BOM、原始数据和实验脚本可复现；
- 不使用诊断准确率或医学有效性等超出证据的表述。

完成H1后仍必须通过M1-SP1、M1-APP1、M1-INT1和M1-V，才能把项目状态更新为“M1完成”。
