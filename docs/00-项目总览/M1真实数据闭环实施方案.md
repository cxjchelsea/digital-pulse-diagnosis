# M1真实数据闭环实施方案

版本：0.1.0；状态：启动中。

## 1. 里程碑定位

M1是D0–D3数字基线冻结后的第一个系统能力里程碑。

M1不以“完成采购”“接通传感器”或“看到波形”为目标，而以建立第一个真实、可信、可追溯、能够反馈下一步动作的数据闭环为目标：

```text
真实设备采集
→ 原始数据完整保存
→ 信号质量与逐搏处理
→ 软件展示和客观参数
→ 接受/重采/换位/停止决策
→ 记录决策并再次采集
```

H1是M1的DAQ实体证据包，但M1还必须同时完成SP-S1、APP-A1和INT-I1。

## 2. M1要回答的问题

1. 真实传感器、ADC和MCU能否稳定输出完整数据？
2. 原始数据是否可以不丢失地保存、重放和追踪版本？
3. 系统能否识别削顶、断线、丢帧、弱信号和明显伪影？
4. 系统能否在可信窗口完成逐搏和基础客观参数？
5. 结果能否与参考PPG进行时序和心率对照？
6. 质量不足时，系统能否阻断正式参数并建议重采、换位或停止？
7. 完全重戴后，系统能否重复获得有效数据并保留失败样本？

## 3. 四条主线交付

### 3.1 DAQ：真实采集与实体证据

由H1完成：

- 可追溯首批BOM和模块版本；
- ESP32-S3真实定时采样；
- 动态脉搏候选通道；
- 静态载荷通道；
- 参考PPG通道；
- D1正式协议与USB传输；
- 原始帧、设备事件、校准和硬件版本；
- 台架、仿体、探头和重戴实验数据。

### 3.2 SP-S1：真实单点信号处理

- CRC、序号、时间戳和会话完整性；
- ADC计数到电压/载荷等工程单位；
- 削顶、断线、弱信号、基线不稳和明显运动伪影；
- 基础实时因果滤波和离线复核滤波分离；
- 心搏候选检测、逐搏切分和异常搏动标记；
- 与参考PPG的时间对齐；
- 质量类别、原因和可解释特征；
- 处理版本、代码SHA和参数记录。

### 3.3 APP-A1：真实会话与基础分析软件

- 真实设备握手和会话创建；
- 原始帧优先落盘；
- 事件、样本、处理结果和报告分层保存；
- 完整离线重放；
- 实时显示脉搏、静态载荷、PPG、设备状态和质量；
- 基础心率、心搏间期和质量摘要；
- 硬件、固件、校准、算法和参数版本追踪；
- 质量失败时不生成正式参数；
- H1/M1实验报告初版。

### 3.4 INT-I1：质量驱动的采集决策

I1不自动施压，也不使用复杂模型。首版采用规则、状态和审计记录：

- `accept`：当前记录满足M1质量门；
- `retry_same_position`：同一位置重新采集；
- `reposition`：提示操作者重新定位探头；
- `stop`：电气、设备、数据或质量问题不适合继续；
- `manual_review`：规则冲突或置信度不足，保留数据等待复核。

每次决策记录输入质量、设备状态、阈值版本、动作、原因和结果。

## 4. 工作分解

| ID | 工作包 | 依赖 | 输出 |
|---|---|---|---|
| M1-00 | 接口与证据边界复核 | D0–D3 | 正式协议、Schema、会话、校准和报告接口清单 |
| H1-A | 采购冻结 | M1-00 | 可下单BOM、供应商、原理图、价格、交期和备选方案 |
| H1-B | 到货与电气验收 | H1-A | 模块版本、电气检查、ADC短接零噪声和隔离记录 |
| H1-C | 真实数据链路 | H1-B | MCU、ADC、USB、正式协议、原始落盘和完整性统计 |
| H1-D | 传感器与探头证据 | H1-C | 零噪声、漂移、迟滞、重复加载、仿体响应和决策矩阵 |
| M1-SP1 | S1处理实现 | H1-C首批数据 | 真实完整性、滤波、逐搏、质量和PPG对齐 |
| M1-APP1 | A1软件实现 | H1-C首批数据 | 真实会话、重放、实时界面、基础参数和报告 |
| M1-INT1 | I1决策实现 | M1-SP1质量输出 | 接受、重采、换位、停止和审计记录 |
| H1-E | 手动单点与重戴 | H1-D、M1-SP1基础可用 | 30–60秒记录、至少3次重戴、成功和失败样本 |
| M1-V | 综合验收 | 全部 | M1验收报告和是否进入M2的结论 |

## 5. 执行策略

M1不是完全串行项目。

- H1-A和H1-B以硬件调研、电气风险为主；
- H1-C一旦产生首批稳定台架数据，M1-SP1和M1-APP1立即启动；
- M1-INT1在质量输出结构稳定后启动，不等待所有人体数据；
- H1-D继续提供候选、失败模式和探头数据；
- H1-E只在电气、仿体、完整性、质量阻断和低风险阶段门通过后执行；
- 所有真实数据都进入同一会话、版本和报告体系，禁止手工挑选最佳曲线作为唯一证据。

## 6. 数据与证据结构

每次真实会话至少保留：

```text
session-id/
├── manifest.json
├── raw_frames.bin
├── events.jsonl
├── samples.parquet
├── calibration/
├── processed/
│   ├── quality.parquet
│   ├── waveform.parquet
│   ├── beats.parquet
│   └── features.json
├── decisions.jsonl
└── report.json
```

`manifest.json`至少包含：

- 硬件、模块、传感器和探头版本；
- 固件、协议、校准和配置版本；
- 软件代码SHA和处理参数版本；
- 操作者、匿名受试者、左右手、位置和采集条件；
- 会话完成状态和失败原因。

原始人体数据不得提交公开仓库。仓库只保存Schema、脚本、充分匿名示例和验收摘要。

## 7. M1质量门

### 7.1 数据完整性门

- CRC错误、序号跳变和时间戳异常可检测；
- 会话异常中断可识别；
- 原始帧优先落盘；
- 重放能够重建相同样本和事件顺序；
- 同一输入、代码和参数版本输出一致。

### 7.2 电气与信号门

- ADC不持续削顶；
- 断线、开路、短路或固定值可识别；
- 零噪声和漂移有真实记录；
- 仿体重复脉动至少10次可复现；
- 真实单点记录连续30–60秒；
- 与PPG的逐搏匹配和心率误差有量化结果。

### 7.3 软件与决策门

- 原始、处理、事件和决策可追溯；
- UI阻塞不影响原始数据保存；
- 质量失败不输出正式参数；
- I1决策可解释并有规则版本；
- 接受、重采、换位和停止路径均有测试或真实证据；
- 决策不能覆盖安全状态机和人工停止。

### 7.4 重戴门

- 完全拆下并重戴至少3次；
- 每次记录成功或失败；
- 不删除失败会话；
- 报告重戴有效率、主要失败原因和改进建议。

## 8. M1完成定义

只有以下全部成立，M1才能标记完成：

- H1实体证据包通过；
- S1真实单点处理通过；
- A1真实会话和基础分析通过；
- I1质量驱动决策通过；
- 30–60秒真实记录与PPG对照完成；
- 至少3次重戴和失败数据完成；
- 每个正式结果可以追溯到原始数据、硬件/固件、校准、代码和参数版本；
- 验收报告明确已验证能力、失败模式和未验证边界；
- 不使用医学有效性、诊断准确率或人体安全载荷等超出证据的表述。

## 9. 非目标

M1不完成：

- 自动施压；
- 多压力自适应推荐；
- 多人泛化模型；
- 自动寻脉；
- 阵列和定制PCB；
- 无线和电池；
- 脉象、疾病或治疗结论。

## 10. 退出与下一阶段

M1通过后进入M2“可信单点分析”。M2不优先增加硬件，而是冻结单点采集组合，重点完善质量解释、逐搏、客观参数、参考对照和单次报告。

M1未通过时：

- 硬件或电气失败：回到H1-A/H1-B；
- 数据链路失败：回到H1-C；
- 传感器或结构失败：回到H1-D；
- 处理失败：回到M1-SP1；
- 软件追溯失败：回到M1-APP1；
- 决策误用或无法解释：回到M1-INT1；
- 不通过增加复杂模型掩盖基础问题。
