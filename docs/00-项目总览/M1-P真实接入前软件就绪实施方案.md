# M1-P真实接入前软件就绪实施方案

版本：0.2.0；状态：M1-P0已完成，M1-P1未开始。

## 1. 定位

M1-P是M1“真实数据闭环”内部的真实硬件接入前工作包。

它的目标不是继续无限扩展模拟系统，也不是用模拟结果替代真实设备，而是：

> 在正式下单和真实硬件接入前，把能够确定的数据契约、信号处理结构、分析软件、自适应决策、失败行为和验收门实现完整，使真实接入阶段主要完成数据源替换、参数校准和真实复验。

M1-P与H1-A采购调研并行：

- M1-P负责软件和算法就绪；
- H1-A负责实际型号、供应商、价格、交期、模块原理图和备选方案；
- 默认在M1-PV通过且BOM评审完成后正式下单；
- 长交期器件如需提前购买，必须记录原因、风险、替代方案和不可逆成本。

跟踪Issue：#29。

## 2. 边界

### 2.1 M1-P可以完成

- 未来真实设备必须遵循的数据和文件契约；
- 多通道真实风格模拟器；
- 信号处理的结构、接口、原因代码和确定性测试；
- 会话、原始落盘、重放、界面、报告和版本追踪；
- 质量驱动的接受、重采、换位、人工复核和停止规则；
- 正常和失败场景的端到端验收；
- 真实数据接入适配器接口。

### 2.2 M1-P不能完成

- 真实传感器噪声、漂移、迟滞和批次差异；
- ADC有效分辨率、参考源误差和真实采样抖动；
- 压电保护电路、模拟前端和实际电气安全；
- 探头结构与皮肤耦合；
- 真实运动伪影的统计分布；
- PPG与脉搏通道的真实延迟；
- 真实质量阈值、滤波参数和人体有效率；
- H1或M1正式验收。

所有依赖真实数据的参数必须标记为`pending_h1_calibration`，不得用模拟数据伪装成最终阈值。

## 3. 总体闭环

```text
M1正式数据契约
→ 多通道真实风格模拟数据
→ SP-S1-pre质量与逐搏处理
→ APP-A1-pre会话、展示和报告
→ INT-I1-pre接受/重采/停止决策
→ 决策结果驱动下一次模拟采集
→ 保存原始、处理、报告和决策证据
```

模拟器和未来真实设备只允许在DAQ适配层不同，SP、APP和INT必须复用相同的正式数据结构。

## 4. 工作包

## M1-P0：数据契约与Schema（已完成）

### 状态

M1-P0已冻结五类正式契约与机器可读Schema。M1-P0通过只表示跨层数据结构就绪，不表示M1-P、H1或M1通过，也不开始M1-P1模拟器实现。

### 产物

```text
protocols/
├── m1-sample.schema.json
├── m1-session.schema.json
├── m1-quality.schema.json
├── m1-decision.schema.json
└── m1-report.schema.json

src/digital_pulse/m1_contracts.py
examples/m1/
tests/test_m1_contracts.py
tests/test_m1_schemas.py
```

### 职责边界

| 契约 | 职责 | 不承载 |
|---|---|---|
| M1Sample | 原始采集事实、通道状态、设备状态、主机接收完整性评估 | 最终分析参数、医学结论 |
| M1Session | 会话溯源、配置、版本、完整性摘要、会话相对文件角色 | 绝对路径、真实阈值 |
| M1QualityResult | 窗口级可解释质量标签、原因、指标和处理版本 | 校准后的伪精确置信度 |
| M1Decision | 可审计动作、原因、重采计数、人工覆盖与结果回填 | I1范围外的实际动作执行 |
| M1Report | 报告状态、阻断关系、版本清单和限制声明 | `analysis_allowed=false`时的正式客观参数 |

### 关键规则

- 时间：设备单调时钟使用`device_time_us`；主机接收使用`host_received_at_utc`；禁止无单位`timestamp`；
- 缺失值：原始通道用`value=null`加`status`表达未配置/断线/读失败，禁止用`0`表示缺失；
- 来源：`simulator` / `replay` / `hardware` / `imported`；模拟必须带`scenario_id`、`random_seed`、`simulator_version`；
- 版本：样本级可引用协议/固件/硬件/校准；会话级包含`signal_processing_version`、`decision_rule_version`、`software_commit_sha`、`configuration_digest`；
- `pending_h1_calibration`：真实未知阈值必须显式标记；该状态下`confidence`必须为`null`；
- 完整性：`receive_integrity`是主机解码后的派生评估，不由发送端宣称权威真相；
- 兼容：D0–D3二进制`DataSample`保持不变，经`data_sample_to_m1_sample`适配进入M1层。

### 退出条件

- Schema具有版本号`1.0.0`；
- 示例与Python契约均可被Schema拒绝非法字段/枚举；
- 可选硬件字段不破坏模拟流程；
- 旧协议适配器不修改原协议对象；
- D0–D3回归与D3正式验收保持通过。

## M1-P1：多通道真实风格模拟器

### 通道

- 动态脉搏；
- 静态接触力；
- 参考PPG；
- 设备状态、传感器状态和事件；
- 可配置采样抖动、时钟偏移和通道延迟。

### 场景

至少提供：

1. 正常高质量信号；
2. 无接触；
3. 弱信号；
4. 上下削顶；
5. 基线漂移；
6. 运动冲击；
7. 接触力不稳定；
8. PPG错位或丢失；
9. 丢帧、乱序和时间戳异常；
10. 传感器断线或固定值；
11. 原始落盘失败；
12. 有效时长不足；
13. 同位重采后改善；
14. 重采达到上限仍失败；
15. 人工停止；
16. ABORT和设备故障。

### 约束

- 使用固定随机种子形成黄金场景；
- 模拟器只验证软件行为；
- 传感器响应参数不得写成真实器件实测值；
- 场景配置和预期结果必须版本化。

## M1-P2：SP-S1-pre信号处理预实现

### 功能

- CRC、帧序号、时间戳和会话完整性报告；
- ADC计数到工程单位的版本化换算接口；
- 稳定窗口和有效时长计算；
- 实时因果滤波与离线零相位复核分离；
- 基线漂移、削顶比例、弱信号和运动伪影指标；
- 心搏候选检测和逐搏切分；
- PPG时间对齐和逐搏匹配；
- 质量类别、分数、原因代码和证据；
- 输入ID、代码SHA、配置和参数版本追踪。

### 首版质量类别

```text
good
no_contact
weak_signal
motion_artifact
sensor_saturation
pressure_unstable
unstable_baseline
reference_mismatch
incomplete_data
irregular_or_unknown
```

### 参数策略

参数分为：

- `structural_default`：不依赖真实硬件的结构参数；
- `simulation_only`：仅用于场景回归；
- `pending_h1_calibration`：必须用真实数据校准；
- `frozen_h1`：H1真实复验后才能出现。

M1-P阶段禁止生成`frozen_h1`参数。

## M1-P3：APP-A1-pre分析软件预实现

### 后端

- 统一的数据源适配器接口；
- 模拟会话创建、运行、中止和结束；
- 原始帧优先落盘；
- 样本、事件、质量、逐搏、决策和报告分层保存；
- 完整离线重放；
- 质量失败阻断正式参数；
- 版本和配置哈希追踪；
- M1-P预验收报告。

### 前端

至少展示：

- 数据源和会话状态；
- 动态脉搏、静态载荷和PPG；
- 原始与处理波形；
- 质量状态、原因和有效窗口；
- 逐搏标记与基础心率；
- 决策动作和原因；
- 失败、不完整、停止和人工复核状态；
- 模拟结果和真实结果的明确证据标签。

### 报告

报告必须区分：

- `evidence_source=simulation`；
- `analysis_status=blocked/allowed_for_simulation`；
- `real_hardware_validated=false`；
- 待H1校准的阈值和参数；
- 代码、配置、Schema和规则版本。

## M1-P4：INT-I1-pre规则决策引擎

### 动作

- `accept`；
- `retry_same_position`；
- `reposition`；
- `manual_review`；
- `stop`；
- `abort_and_release`。

### 优先级

```text
安全
→ 原始数据与会话完整性
→ 信号质量
→ 是否达到实验目标
→ 采集效率
```

### 必须实现

- 最大重采次数；
- 防止无限决策循环；
- 原因代码和人类可读解释；
- 规则版本和关键输入快照；
- `decisions.jsonl`；
- 人工覆盖不丢失原建议；
- 相同输入、配置和规则得到相同决策；
- 安全和完整性失败不能被质量分数覆盖。

## M1-P5：模拟场景与验收矩阵

| 场景 | SP预期 | INT预期 | APP预期 |
|---|---|---|---|
| 正常且时长足够 | `good` | `accept` | 允许模拟参数，标记非真实证据 |
| 时长不足 | `incomplete_data` | `retry_same_position` | 阻断正式参数 |
| 连续弱信号 | `weak_signal` | 重采后`reposition` | 展示换位提示 |
| 削顶 | `sensor_saturation` | `stop` | 标记硬件检查 |
| 严重丢帧 | `incomplete_data` | `stop` | 会话不完整 |
| PPG冲突 | `reference_mismatch` | `manual_review` | 等待复核 |
| 重采改善 | `good` | `accept` | 关联前后两次记录 |
| 达到重采上限 | 失败 | `stop`或`manual_review` | 不再自动重试 |
| ABORT | 不分析 | `abort_and_release` | 停止并禁止继续输出 |

每个场景都必须有：

- 固定配置；
- 预期质量；
- 预期动作；
- 预期会话状态；
- 自动测试节点；
- 可重放产物。

## 5. M1-PV正式验收

M1-PV通过需要：

- M1-P0至P5全部完成；
- 模拟器和未来硬件适配器使用相同接口；
- Schema、报告和决策均有版本；
- 原始、处理、事件、报告和决策可完整重放；
- 质量失败无法绕过并输出正式参数；
- 决策不会无限重试；
- 正常与失败场景均有确定性测试；
- Web生产构建和Python测试通过；
- 验收产物记录代码SHA、配置哈希和证据来源；
- 所有真实未知量列入H1校准清单；
- 报告明确M1-P通过不等于M1、H1或真实设备能力通过。

## 6. 与采购的关系

H1-A在M1-P期间并行完成：

- 实际店铺和商品链接；
- 日期、价格、运费、库存和交期；
- 完整料号和模块版本；
- 官方数据手册和模块原理图；
- 供电、电平、接口和关键引脚；
- 验证假设和替代方案。

默认下单门：

```text
M1-PV通过
＋ H1-A采购与电气风险评审通过
＝ 可以正式下单
```

提前下单例外只用于明确长交期或库存风险，且必须记录：

- 提前购买理由；
- 软件接口尚未冻结部分；
- 买错或模块版本不符的损失；
- 备选方案；
- 决策人和日期。

## 7. 真实接入后的转换

H1-B/H1-C开始后：

1. 保留M1-P所有黄金场景作为回归；
2. 新增硬件数据源适配器，不改SP/APP/INT核心接口；
3. 用真实零噪声、漂移、载荷和PPG数据校准参数；
4. 将参数从`pending_h1_calibration`升级为候选真实配置；
5. 在独立保留数据上冻结正式阈值；
6. 重跑模拟回归和真实场景验收；
7. 只有M1-V通过后，才宣称真实数据闭环完成。

## 8. 非目标

M1-P不实现或不宣称：

- ESP32真实固件和ADC驱动；
- 真实电气性能；
- 人体安全载荷；
- 真实心率误差、有效率和重复性；
- 自动施压；
- 多压力推荐；
- 自动寻脉；
- 疾病、脉象或治疗结论。
