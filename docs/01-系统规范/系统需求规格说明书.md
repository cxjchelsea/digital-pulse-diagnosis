# 系统需求规格说明书

版本：0.2.0  
适用范围：D0–D3数字原型、H1–H5实体验证；H6为可选外部研究。

## 1. 系统边界与阶段语义

系统由采集硬件、信号处理和分析软件三层组成。

- D0（原P0）：基础合成采集、存储、处理、API和Web闭环，已验收；
- D1：设备抽象、固件行为模拟、虚拟串口、握手、能力与重连；
- D2：版本化标定、多压力实验、质量门控与自动报告；
- D3：自动施压被控对象、控制器、安全状态机与故障注入；
- H1–H5：依次验证真实单点采集、接触力/结构、自动施压、多人重复性和自动寻脉；
- H6：仅在医生、伦理和专业标注条件具备时启动，不属于项目主体完成条件。

D阶段证明软件和模型内行为成立，不证明真实传感器、机械结构、人体安全或医学有效性。D1–D3全部通过后才允许冻结并采购H1最小硬件包。

## 2. 优先级

- 必须：对应阶段退出前必须满足；
- 应当：不阻塞当前阶段，但必须在注明的后续阶段前满足；
- 可选：不影响项目主体完成的扩展能力。

## 6. 阶段退出规则

- D0退出条件以已归档的《P0测试与验收计划》和《P0阶段验收报告》为准；
- D1、D2、D3分别满足《D1–D3数字原型扩展实施总方案》的退出条件；
- D1–D3未全部通过时，不启动H1下单和实物验收；
- H1–H5必须使用对应真实硬件和真实实验数据，模拟结果不能替代；
- H6未满足外部条件时保持暂停，不能用开源资料生成的标签替代专业真值；
- 任何阶段变更协议、标定、硬件或算法版本后，受影响的验证必须重新执行。
