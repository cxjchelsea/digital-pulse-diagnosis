# 接口与通信协议

版本：0；状态：D0–D3冻结的可执行二进制基线；M1跨层契约见`protocols/m1-*.schema.json`。

## 1. 传输规则

- 字节序：小端；
- 帧边界：固定帧头＋显式负载长度；
- 完整性：CRC32；
- 时间：设备启动后的单调微秒时间，不使用系统日期时间；
- 正式数据：二进制；调试日志不得混入二进制通道。

## 2. 帧结构

| 字段 | 类型 | 字节 | 说明 |
|---|---:|---:|---|
| magic | uint16 | 2 | `0x4450` |
| protocol_version | uint8 | 1 | 当前为0 |
| message_type | uint8 | 1 | 1数据、2事件、3命令、4响应 |
| payload_length | uint16 | 2 | 负载字节数 |
| frame_sequence | uint32 | 4 | 每帧递增 |
| device_time_us | uint64 | 8 | 单调时间 |
| payload | bytes | 可变 | 由消息类型定义 |
| crc32 | uint32 | 4 | 覆盖帧头和负载 |

## 3. 数据负载

| 字段 | 类型 | 单位/语义 |
|---|---:|---|
| sample_sequence | uint32 | 样本递增序号 |
| pulse_raw | int32 | 原始动态通道计数 |
| force_raw | int32 | 原始载荷通道计数 |
| reference_raw | int32 | 原始参考通道计数 |
| motor_position | int32 | 执行器位置计数 |
| target_force | int32 | 目标载荷的协议整数表示 |
| device_state | uint16 | 状态枚举 |
| status_flags | uint32 | 位标志 |

P0模拟器暂以毫单位编码载荷。真实硬件接入前必须在能力响应中携带缩放和校准信息，不能把P0编码当作人体压力标准。

## 4. 状态与故障

状态：BOOT、SELF_TEST、IDLE、APPROACH、CONTACT、STABILIZE、ACQUIRE、STEP、RETRACT、FAULT。

故障位：上下限位、急停、脉搏通道饱和、载荷通道饱和、传感器断线、缓冲溢出和链路异常。

## 5. 兼容规则

- 未知版本：拒绝并记录；
- 未知消息类型：拒绝并记录；
- 长度不符：整帧无效；
- CRC不符：整帧无效，不尝试修复；
- 序号跳变：保存前后数据并记录缺口；
- 时间戳回退：会话标记为不完整；
- P0不实现重发，原始数据流优先保持实时性。

可执行实现见`src/digital_pulse/protocol.py`。

## 6. 与M1跨层契约的关系

二进制帧协议继续服务DAQ传输，字段含义不变：

| 协议字段 | M1Sample映射 |
|---|---|
| `frame_sequence` / `device_time_us` | 同名字段 |
| `pulse_raw` | `pulse.value` |
| `force_raw` | `load.value` |
| `reference_raw` | `ppg.value` |
| `target_force` | `target_load_raw` |
| `motor_position` | `motor_position_raw` |
| `device_state` | 字符串状态名 |
| `status_flags` | `fault_flags`与通道`clipping`/`status` |

兼容规则：

- 不修改、不删除现有`DataSample`字段，不改变CRC与字节序；
- SP、APP、INT只消费M1契约，不直接依赖串口帧类；
- 旧`DataSample`经`digital_pulse.m1_contracts.data_sample_to_m1_sample`显式适配；
- `receive_integrity`由主机解码后填写，表示接收侧评估，不由发送端宣称权威真相；
- 通道缺失用`value=null`加`status`表达，传感器断线时不得把协议中的`0`直接解释为有效读数。
