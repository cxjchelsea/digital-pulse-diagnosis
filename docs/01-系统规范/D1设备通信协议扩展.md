# D1设备通信协议扩展

本文件扩展D0协议v0，不改变既有DATA帧。公共帧结构、字节序、长度和CRC规则仍以《接口与通信协议》为准。

## 1. 控制帧载荷

COMMAND和RESPONSE载荷前缀均为：

| 字段 | 类型 | 说明 |
|---|---|---|
| command | uint16 LE | 命令码 |
| request_id | uint32 LE | 请求关联ID |
| body | UTF-8 JSON object | 参数或响应正文；键排序编码 |

COMMAND正文是参数对象。RESPONSE正文固定包含`status`、`error`和`data`。

## 2. 枚举

| 命令 | 值 |
|---|---:|
| HELLO | 1 |
| CAPABILITIES | 2 |
| START | 3 |
| STOP | 4 |
| ABORT | 5 |

| 响应状态 | 值 |
|---|---:|
| ACK | 0 |
| NACK | 1 |

| 错误 | 值 |
|---|---:|
| NONE | 0 |
| INVALID_COMMAND | 1 |
| INVALID_STATE | 2 |
| INVALID_ARGUMENT | 3 |
| UNSUPPORTED | 4 |
| INTERNAL_ERROR | 5 |

## 3. 能力字段

HELLO和CAPABILITIES至少返回`device_id`、`firmware_version`、`protocol_version`、`sample_rates_hz`、`channels`、`supports_abort`、`calibration_version`和`state`。

未知命令、非法状态和非法参数必须NACK，不能静默忽略。ABORT优先于普通命令，由设备侧执行安全退回语义。

## 4. 流解析

- 传输层提供任意长度字节块，不保证一读一帧；
- 解析器必须保留不完整尾部；
- 完整帧可以粘连在同一字节块；
- CRC、版本、类型和长度错误必须显式失败；
- 收到的原始字节必须先写入会话文件，再解析派生样本。

## 5. H1兼容要求

真实串口实现必须满足`DeviceTransport`接口，并通过D1同一套分片、握手、状态、断连和原始落盘测试。不得为适配某块开发板绕过协议或在Web端直接拥有串口。
