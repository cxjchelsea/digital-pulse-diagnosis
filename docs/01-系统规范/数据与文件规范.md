# 数据与文件规范

## 1. 数据层级

| 层 | 内容 | 规则 |
|---|---|---|
| L0 | 原始二进制帧和事件 | 永不覆盖 |
| L1 | 校准后的工程单位数据 | 引用校准版本 |
| L2 | 质量、滤波和逐搏结果 | 引用算法与参数 |
| L3 | 特征和模型输入 | 可完全再生 |
| L4 | 模型输出和人工标注 | 引用模型/标注者版本 |

M1跨层正式契约（机器可读）见：

```text
protocols/m1-sample.schema.json
protocols/m1-session.schema.json
protocols/m1-quality.schema.json
protocols/m1-decision.schema.json
protocols/m1-report.schema.json
```

运行时结构见`src/digital_pulse/m1_contracts.py`。M1Sample承载L0原始采集事实；M1QualityResult/M1Decision/M1Report承载派生结果，不得回写覆盖原始值。

## 2. 会话目录

```text
session-id/
├── manifest.json
├── raw_frames.bin
├── events.jsonl
├── samples.parquet
├── processed/
│   ├── quality.parquet
│   ├── waveform.parquet
│   ├── beats.parquet
│   └── features.json
└── report.json
```

P0至少生成`manifest.json`和`raw_frames.bin`。其余文件随着模块实现增加。

M1Session.files只记录会话相对路径和逻辑角色（`raw_frames`、`events`、`samples`、`quality`、`beats`、`decisions`、`report`、`manifest`），禁止写入某台电脑的绝对路径。

## 3. Manifest必填字段

历史P0会话manifest仍兼容：

- schema_version；
- session_id；
- source_type：simulator/device；
- started_at_utc；
- completed；
- sample_rate_hz；
- pressure_profile；
- protocol_version；
- simulator或firmware版本；
- hardware_revision；
- sensor_id、probe_revision、calibration_id；
- frame_count、first_sequence、last_sequence；
- crc_error_count、missing_frame_count；
- code_commit；
- processing_parameters。

M1正式会话契约在此基础上扩展并规范化：

- `source_type`：`simulator` / `replay` / `hardware` / `imported`（旧manifest中的`device`在适配时应映射为`hardware`）；
- `completion_reason`：`completed=false`时必填；
- 版本清单：`calibration_version`、`signal_processing_version`、`decision_rule_version`、`software_commit_sha`、`configuration_digest`；
- `parameter_status`：真实未知参数使用`pending_h1_calibration`或`synthetic_only`；
- `limitations`：至少声明工程边界，不得暗示医学用途。

未知值使用`null`，不得伪造占位测量值；原始通道缺失不得用`0`伪装。

## 4. 原始数据与派生数据边界

- 原始ADC计数只出现在M1Sample通道`value`或二进制帧中；
- 工程单位、滤波结果、逐搏和质量结果属于派生层，必须引用处理/参数版本；
- `analysis_allowed=false`时，M1Report不得填充正式客观参数；
- 模拟阶段报告必须带`synthetic_input`与`not_for_medical_use`限制。

## 5. 版本与校准状态

- `schema_version`当前冻结为`1.0.0`；
- 需要真实数据决定的阈值、滤波参数、PPG时延和人体有效门槛标记为`pending_h1_calibration`；
- 在`pending_h1_calibration`状态下，质量结果的`confidence`必须为`null`，避免伪精确置信度。

## 6. 隐私

- 公开仓库只允许合成数据和无身份示例；
- 人体数据目录必须被Git忽略；
- `subject_id`使用随机ID；
- 不保存非研究必需的姓名、电话和精确生日；
- 后续临床合作前重新制定授权、加密、访问控制和保留期限。
