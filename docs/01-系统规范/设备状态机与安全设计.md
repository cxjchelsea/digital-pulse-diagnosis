# 设备状态机与安全设计

## 1. 原则

- 安全闭环在MCU本地；
- 分析软件失联时仍可退回；
- 故障优先级高于采集命令；
- 硬件安全上限不能由普通会话参数覆盖；
- P0只验证状态语义，不宣称人体安全性。

## 2. 状态转换

```mermaid
stateDiagram-v2
    [*] --> BOOT
    BOOT --> SELF_TEST
    SELF_TEST --> IDLE: 通过
    SELF_TEST --> FAULT: 失败
    IDLE --> APPROACH: 开始
    APPROACH --> CONTACT: 检测接触
    CONTACT --> STABILIZE: 设置目标
    STABILIZE --> ACQUIRE: 稳态成立
    ACQUIRE --> STEP: 平台完成
    STEP --> STABILIZE: 下一平台
    STEP --> RETRACT: 全部完成
    RETRACT --> IDLE: 完全卸载
    APPROACH --> RETRACT: 急停/超限/失联
    CONTACT --> RETRACT: 急停/超限/失联
    STABILIZE --> RETRACT: 急停/超限/失联
    ACQUIRE --> RETRACT: 急停/超限/失联
    RETRACT --> FAULT: 无法卸载
```

## 3. P1前必须补齐的硬件安全机制

- 上下机械限位；
- 常闭急停；
- 独立最大行程；
- 本地载荷上限；
- 载荷传感器断线检测；
- 电机卡滞/超时；
- 看门狗；
- 断电手动释放；
- 低压供电与电气隔离评估。

任何人体测试前必须在仿体上执行故障注入测试。
