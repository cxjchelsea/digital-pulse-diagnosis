## 2. 正式验收门禁

`formal_acceptance` 仅在以下门禁全部为真时成立：

- workspace_clean
- pytest_passed
- unittest_passed
- web_build_passed
- normal_profile_passed
- closed_loop_matrix_passed
- abort_runtime_passed
- full_chain_1800s_passed
- traceability_passed
- config_hashes_present
- evidence_source_valid
- ci_sha_matches
- no_skip_web / no_skip_unittest

`--skip-web`、`--skip-unittest`、工作区脏、任一验证失败均导致非正式验收。
`--allow-dirty` 只允许写出草稿，不能使 `formal_acceptance=true`。

证据来源由 `GITHUB_ACTIONS` 环境变量自动判定；本地不能伪造 `github-actions`。
CI 中还会校验 `GITHUB_SHA` 与 `git rev-parse HEAD` 一致。

## 3. 配置与Profile阈值

Profile验收阈值由 `ProfileAcceptanceConfig` 定义（默认稳定时间≤3.0s、稳态误差≤2.0 au、超调≤10%），不属于设备侧 SafetyConfig。

验收产物保存完整 `plant` / `controller` / `safety` / `timing` / `profile_acceptance` 配置及对应 SHA-256（含 `combined_sha256`）。

## 4. 安全证据分层

| 层次 | 含义 | 证据位置 |
|---|---|---|
| 检测瞬间安全响应 | 故障识别、优先级、检测延迟、瞬时命令与目标态 | `d3_fault_matrix` / 14类矩阵测试 |
| 完整卸载结果 | 停止加压、开始退回、接触解除、下限位、IDLE | `d3_closed_loop` 可退回用例 |
| 锁存故障结果 | 急停/卡滞/看门狗零输出并保持 `FAULT_LATCHED`，不虚构主动退回 | `d3_closed_loop` 锁存用例 |
| ABORT后命令 | 自 abort_processed_tick 起所有tick命令≤0 | runtime 报告 `max_command_after_abort` |

## 5. 30分钟模型时长结果

完整链路测试：`run_full_chain_long_hold(duration_s=1800)`。

覆盖模块：`plant`、`pid`、`safety`、`device_state_machine`、`heartbeat`。

具体数值、哈希与配置以最新 `artifacts/d3-acceptance/acceptance.json` 为准，不在本文手填。

## 6. ABORT API/Web闭环

| 接口 | 作用 |
|---|---|
| `POST /api/experiments/d3/runs` | 创建可运行会话（可 `hold` 停留于 ACQUIRE） |
| `GET /api/experiments/d3/runs/{run_id}` | 查询状态/载荷/位移/命令/tick |
| `POST /api/experiments/d3/runs/{run_id}/abort` | 设备侧 ABORT（幂等） |
| `GET /api/experiments/d3/runs/{run_id}/events` | 会话事件与时间线 |

ABORT后报告记录：`abort_request_tick`、`abort_processed_tick`、`retract_tick`、`idle_tick`、`unload_duration_s`、`max_command_after_abort`、`positive_command_ticks_after_abort`。

## 9. 证据边界

本报告证明数字模型和软件安全逻辑在冻结配置下的行为。它不证明：

- 真实执行器推力、制动、卡滞和断电释放；
- 真实传感器量程、漂移、失效诊断或限位可靠性；
- 真实结构强度、接触面积、夹伤风险或人体安全载荷；
- 任何临床、诊断、脉象或治疗有效性。

所有真实硬件未知量仍进入 H1。D3正式冻结后只允许进入H1采购与台架验证，不允许直接进入人体自动施压实验。
