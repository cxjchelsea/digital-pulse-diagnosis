# M1-P2测试与验收计划

版本：0.1.0；状态：设计冻结，等待P2A实现。

## 1. 验收目标

M1-P2验收证明：

- SP-S1-pre只根据正式M1输入和参数处理数据；
- 质量结果可解释且符合冻结M1QualityResult Schema；
- 同一输入和参数结果确定；
- 模拟器oracle不会进入生产处理路径；
- integrity/safety失败不能被后续滤波覆盖；
- simulation-only参数不会被描述为真实H1参数；
- D3与M1-P1正式验收无回归。

M1-P2验收不证明：

- 真实传感器性能；
- 人体有效率；
- 医学分类；
- 最优滤波频带；
- H1/M1通过。

## 2. 测试层级

## 4. P2B测试

建议新增：

```text
tests/test_m1_sp_metrics.py
tests/test_m1_sp_quality.py
tests/test_m1_sp_quality_projection.py
```

### 4.1 metric公式

每个正式metric测试：

- 手工构造小数组可解析；
- 边界值；
- 空/全invalid行为；
- 浮点有限；
- 公式版本化。

### 4.2 quality precedence

构造多异常窗口确认：

```text
data integrity > no contact > saturation > duration > motion > baseline > weak > reference > manual review > acceptable
```

若同一窗口同时weak+sat，primary必须`saturated`。

### 4.3 formal projection

每个输出必须：

- `M1QualityResult.validate_schema()`通过；
- reason code全部属于冻结enum；
- metrics没有未知key；
- score=null；
- confidence=null；
- parameter_status=synthetic_only；
- window_id确定性。

## 7. 16个单attempt场景验收矩阵

以下为M1-P2算法预期，不等同于M1-P1测试oracle的reason code字符串。

| M1-P1场景 | SP-S1-pre预期 | 正式reason | 备注 |
|---|---|---|---|
| normal_high_quality | `acceptable` | `[]` | 可分析 |
| weak_signal | `weak_signal` | `weak_amplitude` | simulation-only阈值 |
| no_contact | `no_contact` | `no_contact` + optional `near_constant` | sensor仍connected |
| upper_saturation | `saturated` | `upper_saturation` | raw clipping优先 |
| lower_saturation | `saturated` | `lower_saturation` | raw clipping优先 |
| baseline_drift | `unstable_baseline` | `unstable_baseline` | raw trend evidence |
| motion_artifact | `motion_artifact` | `motion_artifact` | 不读取FaultKind |
| unstable_load | `manual_review_required` | `manual_review_requested` | load细节仅internal evidence |
| ppg_misalignment | `reference_mismatch` | `reference_mismatch` | PPG为参考证据 |
| insufficient_duration | `insufficient_duration` | `too_short`，可加`insufficient_beats` | sim-only duration |
| frame_loss | `data_integrity_failure` | `sequence_gaps` | 硬门 |
| timestamp_regression | `data_integrity_failure` | `timestamp_errors` | 硬门 |
| sensor_disconnection | `data_integrity_failure` | `sensor_disconnected` | 不等于no_contact |
| raw_persistence_failure | `data_integrity_failure`或基于partial输入的受控阻断 | `persistence_failed` | 以manifest事实为准 |
| abort | `blocked_before_quality` | 无正式quality | safety事实 |
| device_fault | `blocked_before_quality` | 无正式quality | reason enum不足时不伪造 |

## 8. multiattempt验收

P2不执行INT。

### retry_improves

逐attempt独立处理：

```text
attempt1 weak_signal → weak_signal
attempt2 normal_high_quality → acceptable
```

P2不得因为看到第二次改善而生成`accept`决策。

### retry_still_fails

三个attempt都独立输出weak_signal。

P2不得：

- 自动停止；
- 自动reposition；
- 计算retry_count决策。

这些属于P4。

## 9. oracle隔离测试

这是M1-P2关键反循环自证门。

至少实现两类测试：

### 9.1 删除oracle

```text
复制会话目录
删除 scenario.json / expected.json
运行Replay + SP
```

结果必须与原目录相同。

### 9.2 篡改oracle

只修改`expected.json`中的预期label，不修改samples/manifest。

SP输出必须完全不变。

若生产代码受到oracle变化影响，验收直接失败。

## 17. 停止条件

出现以下情况停止：

- 需要改M1QualityResult Schema；
- 需要按scenario_id分类才能通过；
- normal与异常场景在观测metric上无法区分且只能硬编码；
- causal测试证明使用未来数据；
- replay与direct结果不一致；
- confidence出现非null伪精度；
- D3或M1-P1正式验收回归；
- 引入重大依赖未经评审。
