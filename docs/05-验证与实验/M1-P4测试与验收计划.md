# M1-P4测试与验收计划

版本：`0.1.0-p4-testplan`；状态：**规划冻结候选（文档-only）**。

Baseline：`main@fffbf43070d5dcbb4ba748e9ae57e70509f8bac3`。

规则版本目标：`i1-pre-0.1.0`。策略：`i1-policy-v1`，`max_retry_count=2`。

本文件不新增测试代码。P4A 起按子阶段落地。

## 1. 原则

- TDD：每个可观察规则先有失败测试，再有最小实现
- Oracle 隔离：生产 INT 对模拟器期望 metadata 的 import/依赖 = 0
- Fail-closed：不完整真理不得 `accept`
- 不削弱既有 D3/P1/P2/P3/Web/P3F 门禁
- 不把决策重放做成动作执行

## 2. 按子阶段的测试责任

### P4A

- DecisionContext 构造：只接受结构化事实；拒绝波形/oracle 字段
- reason 投影：详细码 → 规范码；稳定排序；无重复
- 六动作覆盖与预留动作拒绝
- 优先级冲突表（架构文档 §7.1）逐条
- retry 比较：`retry_count < 2` vs `>= 2`
- `decision_id` 对时钟/路径不敏感
- 同一 DecisionContext + 配置 → 同一 action / reasons / fingerprint
- `quality_reference`：有质量结果则指向 `session_id+window_id`；pre-quality 为 `null`
- `accept` 不要求、也不产生正式参数

### P4B

- append-only：改写历史行必须失败
- 不完整 JSONL 尾行 fail-closed
- 重复 `decision_id` 字节等价幂等 / 不等价冲突
- 锁与崩溃：无部分可见决策
- 覆盖事件不擦除原 `M1Decision`
- outcome 只经事件变迁
- 只读重放与写入路径分离

### P4C

- RetryScope 重建
- `retry_improves` / `retry_still_fails` 序列
- 耗尽后禁止 `retry_same_position`
- reposition acknowledgement 之前不得重置计数
- 无输入时禁止 reposition/retry 自循环
- `no_contact` 不消耗同位预算

### P4D

- 新报告不覆盖 `app/runs/<run_id>/report.json`
- `decision_summary` 与 ledger 链接
- pre-H1 `objective_parameters=null` 即使 action=accept
- `not_for_medical_use` 仍在
- 查询 API 为投影，非真理源

### P4E

- 16 单场景 + 2 多计划全序列
- 聚合 `m1-p4-acceptance-v1`
- 独立 Final Review 攻击项（见实施方案）

## 3. Oracle 隔离测试（P4E 必过）

对同一冻结 P3 输入：

1. 基线决策
2. 删除 `expected.json` → 同一决策
3. 篡改 `expected_int_action` → 同一决策
4. 篡改 scenario expected reason/action metadata → 同一决策

静态检查：生产 INT 模块不得 import / 打开 `scenario.json`、`expected.json`、`expected_int_action`、`ScenarioDefinition.expected_int_action`。

特别：`retry_still_fails` 第三次不得复制 AttemptSpec 上的 `retry_same_position` oracle。

## 4. 安全优先级测试

| 输入组合 | 期望 |
|---|---|
| acceptable + emergency stop | `abort_and_release` |
| weak signal + device fault | `abort_and_release` |
| acceptable + raw persistence failed | `stop` |
| retry limit + emergency stop | `abort_and_release` |
| manual-review quality + device fault | `abort_and_release` |
| operator stop + acceptable | `stop` |
| sensor_disconnection 无 device_fault | `stop`（不得 abort） |
| `device_state=FAULT` 仅因断线 | `stop`（不得仅因 FAULT abort） |

安全违反次数目标：0。

## 5. 确定性测试

同一 `DecisionContext`、`rule_version`、policy、history → 相同：

- action
- 规范 reason_codes（含顺序）
- semantic fingerprint
- `decision_id`
- configuration digest

显式注入的 `decided_at_utc` 可以不同，但不得改变语义身份。

禁止：集合无序、重复 reason、求值内读系统时钟。

## 6. Fail-closed 输入

必须拒绝并记录，不得猜动作：

缺失 session；APP run 缺失/损坏；SP 溯源缺失；quality reference 损坏；非法 `retry_count`；`retry_count > max_retry_count`；未知 `device_state`；非法 policy digest；rule-version 不匹配；ledger 损坏；不完整 JSONL 末行。

未知但无安全 abort：`manual_review` 或 `stop`（见架构文档 §21），永不默认 `accept`。

## 7. 场景与序列清单

### 7.1 16 单次

`normal_high_quality`，`weak_signal`，`no_contact`，`upper_saturation`，`lower_saturation`，`baseline_drift`，`motion_artifact`，`unstable_load`，`ppg_misalignment`，`insufficient_duration`，`frame_loss`，`timestamp_regression`，`sensor_disconnection`，`abort`，`device_fault`，`raw_persistence_failure`。

期望动作见架构文档 §13。

### 7.2 序列（至少）

1. 正常 accept
2. weak → retry → accept
3. weak → retry → retry → reposition（`retry_count` 0,1,2）
4. no contact → reposition
5. saturation → stop
6. PPG mismatch → manual review
7. frame loss → stop
8. raw persistence failure → stop
9. emergency stop → abort_and_release
10. device fault → abort_and_release
11. quality acceptable + emergency stop → abort_and_release

### 7.3 多计划

- `retry_improves`：由 quality + history 推导，不读计划 oracle
- `retry_still_fails`：三次弱信号后 `reposition` + `retry_limit_reached`
