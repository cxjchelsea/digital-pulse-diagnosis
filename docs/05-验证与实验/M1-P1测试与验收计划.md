# M1-P1测试与验收计划

版本：0.4.0；状态：P1A/P1B/P1C测试已落地；P1D测试待实现。

## 1. 目标

本计划定义M1-P1多通道真实风格模拟器从P1A到P1D的测试策略、门禁、命令、证据和完成标准。

测试目标不是证明模拟器“像真实人体”，而是证明：

- 输出遵循M1-P0正式契约；
- 多通道时间和心搏关系一致；
- 故障语义确定、可追溯、可区分；
- 保存与重放一致；
- 同一确定性键得到相同结果；
- M1-P0和D0–D3未被破坏。

## 2. 测试层次

| 层次 | 目标 | 主要证据 |
|---|---|---|
| 单元测试 | 时钟、RNG、时间轴、通道和故障组件 | 精确断言 |
| 契约测试 | M1Sample、M1Session和文件结构合法 | JSON Schema与运行时验证 |
| 场景测试 | 每个场景核心语义稳定 | 参数化场景矩阵 |
| 确定性测试 | 同配置输出一致 | 结构比较与内容哈希 |
| 同步测试 | Pulse、Load、PPG共享时间与心搏 | 真值事件和观测关系断言 |
| 会话测试 | 保存、失败恢复、相对路径和摘要 | 临时目录产物 |
| 重放测试 | Replay与原始保存内容一致 | 逐样本比较 |
| CLI测试 | 用户入口、错误码和输出 | subprocess/CLI runner |
| 回归测试 | M1-P0、D0–D3和Web不回退 | 全量CI |

## 4. P1A测试：架构与正常场景

### 4.1 配置验证

必须覆盖：

- 合法`ScenarioConfig`创建成功；
- 未知scenario ID在注册表失败（配置层只做格式校验）；
- duration≤0失败；
- sample rate≤0失败；
- seed类型非法失败；
- UTC起点缺少时区失败；
- 规范化配置摘要稳定；
- 空`fault_schedule`不进入digest；
- 输出目录变化不改变configuration digest。

### 4.2 RNG确定性

- 同根种子派生相同子流；
- 不同子流彼此独立；
- 增加Pulse内部随机调用不改变Load/PPG流；
- P1B第5路`artifact_rng`不扰动前4路；
- 不使用模块级全局随机状态；
- 同场景同种子重复执行输出一致。

### 4.3 DeterministicClock

- 样本数量准确；
- frame sequence连续；
- device time单调；
- 非整除采样率不累积截断漂移；
- host UTC带时区；
- 相同配置时间完全一致；
- 不依赖测试执行时刻。

### 4.4 BeatTimeline

- 心搏索引连续；
- 事件时间单调；
- 固定心率间期正确；
- 受控变化在配置范围内；
- 同seed一致；
- Pulse和PPG引用同一事件序列。

### 4.5 基础通道

- Pulse、Load、PPG每个采样时刻对齐；
- normal场景无null通道；
- 状态全部connected/正常；
- clipping flags为none；
- 无故障标志；
- PPG相对BeatTimeline的时延符合配置；
- Load保持在模拟稳定区间；
- 每条M1Sample通过运行时和JSON Schema验证。

### 4.6 P1A退出门

- 正常场景可完整生成；
- 同种子结构级完全一致；
- 不同seed只改变允许细节；
- 三通道共享时间和心搏；
- M1-P0契约无修改；
- 全量回归通过。

## 5. P1B测试：信号与接触异常（已落地）

每个场景至少断言：

1. 场景可从唯一注册表获取；
2. `ScenarioDefinition`预期元数据存在且不执行INT；
3. 所有样本Schema合法；
4. 故障前/中/后区间语义正确；
5. 数值、status和clipping一致；
6. 同seed输出一致；
7. 不同seed不改变核心场景语义；
8. normal场景指纹无回归；
9. 不产生正式M1QualityResult或M1Decision。

### 5.1 weak_signal

- Pulse幅值显著低于同配置normal基线；
- BeatTimeline不变；
- Load和PPG可用；
- Pulse status不是disconnected；
- expected元数据为weak_signal/retry。

### 5.2 no_contact

- 传感器保持connected；
- Load近零接触；
- Pulse无有效脉动且非null；
- 不用0表示缺失，不用disconnected/read_failed；
- PPG可保持可用；
- expected元数据为no_contact/reposition。

### 5.3 upper/lower_saturation

- 数值真正达到对应合成边界；
- clipping flag方向正确；
- 非故障区间不持续削顶；
- expected reason方向正确。

### 5.4 baseline_drift

- 漂移连续且确定；
- 不改变采样时间；
- 故障区间前后行为可区分；
- BeatTimeline不变；PPG不受影响。

### 5.5 motion_artifact

- 只在配置区间注入；
- 默认影响Pulse和Load，PPG默认不受影响；
- 扰动有界；
- 同seed可复现。

### 5.6 unstable_load

- Load波动超过normal基线；
- status仍connected；
- Pulse耦合只在明确启用时出现；
- 不输出人体压力响应结论。

### 5.7 ppg_misalignment

- Pulse与时间戳不变；
- PPG观测时延达到场景配置；
- PPG仍connected；
- expected元数据为reference mismatch/manual review。

### 5.8 insufficient_duration

- 会话正常完成；
- 设备、传输和通道无故障；
- 样本数符合短时配置；
- expected元数据为insufficient duration/retry。

### 5.9 P1B退出门

- 9个信号与接触场景全部通过；
- 核心语义在多seed下稳定；
- normal场景无回归；
- 全量回归通过；
- D3 formal acceptance通过；
- CI Python与Web build通过。
