# M1-P1测试与验收计划

版本：0.1.0；状态：设计评审中。

## 1. 目标

本计划定义M1-P1多通道真实风格模拟器从P1A到P1D的测试策略、门禁、命令、证据和完成标准。

测试目标不是证明模拟器“像真实人体”，而是证明：

- 输出遵循M1-P0正式契约；
- 多通道时间和心搏关系一致；
- 故障语义确定、可追溯、可区分；
- 保存与重放一致；
- 同一确定性键得到相同结果；
- M1-P0和D0–D3未被破坏。

## 2. 测试层次

| 层次 | 目标 | 主要证据 |
|---|---|---|
| 单元测试 | 时钟、RNG、时间轴、通道和故障组件 | 精确断言 |
| 契约测试 | M1Sample、M1Session和文件结构合法 | JSON Schema与运行时验证 |
| 场景测试 | 每个场景核心语义稳定 | 参数化场景矩阵 |
| 确定性测试 | 同配置输出一致 | 结构比较与内容哈希 |
| 同步测试 | Pulse、Load、PPG共享时间与心搏 | 真值事件和观测关系断言 |
| 会话测试 | 保存、失败恢复、相对路径和摘要 | 临时目录产物 |
| 重放测试 | Replay与原始保存内容一致 | 逐样本比较 |
| CLI测试 | 用户入口、错误码和输出 | subprocess/CLI runner |
| 回归测试 | M1-P0、D0–D3和Web不回退 | 全量CI |

## 3. 测试文件建议

```text
tests/
├── test_m1_simulator.py
├── test_m1_simulator_scenarios.py
├── test_m1_simulator_sessions.py
└── test_m1_simulator_cli.py
```

必要时可拆分辅助fixture，但不应为每个场景建立大量重复文件。

## 4. P1A测试：架构与正常场景

### 4.1 配置验证

必须覆盖：

- 合法`ScenarioConfig`创建成功；
- 非法scenario ID失败；
- duration≤0失败；
- sample rate≤0失败；
- seed类型非法失败；
- UTC起点缺少时区失败；
- 不允许的覆盖字段失败；
- 核心场景语义被覆盖破坏时失败；
- 规范化配置摘要稳定；
- 输出目录变化不改变configuration digest。

### 4.2 RNG确定性

- 同根种子派生相同子流；
- 不同子流彼此独立；
- 增加Pulse内部随机调用不改变Load/PPG流；
- 不使用模块级全局随机状态；
- 同场景同种子重复执行输出一致。

### 4.3 DeterministicClock

- 样本数量准确；
- frame sequence连续；
- device time单调；
- 非整除采样率不累积截断漂移；
- host UTC带时区；
- 相同配置时间完全一致；
- 不依赖测试执行时刻。

### 4.4 BeatTimeline

- 心搏索引连续；
- 事件时间单调；
- 固定心率间期正确；
- 受控变化在配置范围内；
- 同seed一致；
- Pulse和PPG引用同一事件序列。

### 4.5 基础通道

- Pulse、Load、PPG每个采样时刻对齐；
- normal场景无null通道；
- 状态全部connected/正常；
- clipping flags为false；
- 无故障标志；
- PPG相对BeatTimeline的时延符合配置；
- Load保持在模拟稳定区间；
- 每条M1Sample通过运行时和JSON Schema验证。

### 4.6 P1A退出门

- 正常场景可完整生成；
- 同种子结构级完全一致；
- 不同seed只改变允许细节；
- 三通道共享时间和心搏；
- M1-P0契约无修改；
- 全量回归通过。

## 5. P1B测试：信号与接触异常

每个场景使用参数化测试，至少断言：

1. 场景可从唯一注册表获取；
2. 场景ID、版本、seed和digest写入输出；
3. 所有样本Schema合法；
4. 故障开始/结束区间准确；
5. 事件、数值、status和flag一致；
6. expected主类别和原因正确；
7. 同seed输出一致；
8. 不同seed不改变核心场景语义；
9. normal场景无对应异常；
10. 不产生正式M1QualityResult或M1Decision。

### 5.1 weak_signal

- Pulse幅值显著低于同配置normal基线；
- BeatTimeline不变；
- Load和PPG可用；
- Pulse status不是disconnected；
- expected为weak_signal/retry。

### 5.2 no_contact

- Load接触状态为无接触；
- Pulse缺失按null+status表达；
- 不用0表示缺失；
- PPG可保持可用；
- expected为no_contact/reposition。

### 5.3 upper/lower_saturation

- 数值真正达到对应边界；
- clipping flag方向正确；
- 非故障区间不持续削顶；
- expected reason方向正确。

### 5.4 baseline_drift

- 漂移连续且确定；
- 不改变采样时间；
- 故障区间前后行为可区分；
- BeatTimeline不变。

### 5.5 motion_artifact

- 只在配置区间注入；
- 受影响通道与事件一致；
- 正常区间仍保留基础心搏；
- 不把整个会话改写成随机噪声。

### 5.6 unstable_load

- Load波动超过场景内部生成约束；
- Pulse耦合只在明确启用时出现；
- 不输出人体压力响应结论。

### 5.7 ppg_misalignment

- Pulse BeatTimeline保持不变；
- PPG观测时延达到场景配置；
- PPG仍connected；
- expected为reference mismatch/manual review。

### 5.8 insufficient_duration

- 会话正常完成；
- 设备、传输和通道无故障；
- 样本数符合短时配置；
- expected为insufficient duration/retry。

### 5.9 P1B退出门

- 9个信号与接触场景全部通过；
- 核心语义在多seed下稳定；
- 故障证据可追溯；
- normal场景无回归；
- 全量回归通过。

## 6. P1C测试：设备、传输、存储与多attempt

### 6.1 frame_loss

- 输出序号存在预期缺口；
- 后续帧不重新编号；
- missing count正确；
- 丢弃范围写入事件；
- 基础通道生成不被回写；
- session completed=false。

### 6.2 timestamp_regression

- frame sequence默认连续；
- device time出现指定回退或重复；
- timestamp error可检测；
- 通道值顺序保持；
- 重放保留异常，而非自动修复。

### 6.3 sensor_disconnection

- status变为disconnected；
- 对应通道值为null；
- fault flag和事件一致；
- 断线区间外按场景定义恢复或结束；
- 不继续产生正常伪值。

### 6.4 abort

- 设备状态进入ABORT；
- 记录触发原因；
- 不正常完成；
- 后续采样行为符合设计；
- expected action为abort_and_release；
- 普通弱信号不能生成ABORT。

### 6.5 device_fault

- 使用通用故障码；
- 与普通质量场景可区分；
- 完成状态和reason正确；
- 不引入厂商私有语义。

### 6.6 raw_persistence_failure

- 使用FailingSessionSink；
- 在指定写入次数稳定失败；
- 已写证据保留；
- 不输出成功manifest；
- 失败摘要和事件正确；
- 不修改真实文件权限。

### 6.7 retry_improves

- 生成两个独立session；
- sequence ID相同；
- attempt index为1、2；
- 第一次弱信号，第二次改善；
- 最终sequence摘要accepted；
- 不由模拟器执行INT逻辑。

### 6.8 retry_still_fails

- attempt数量固定且有限；
- 每次弱信号；
- 最后预期reposition；
- 不存在无限迭代；
- 真实最大重采次数仍标记待H1校准。

### 6.9 P1C退出门

- 设备、传输、存储故障与信号质量场景可区分；
- 失败会话不伪装完成；
- 多attempt关系可追溯；
- 所有场景确定性通过；
- 全量回归通过。

## 7. P1D测试：会话、重放、CLI与黄金摘要

### 7.1 会话目录

正常场景必须包含：

- `manifest.json`
- `samples.jsonl`
- `events.jsonl`
- `scenario.json`
- `expected.json`
- `summary.json`

断言：

- 所有引用为相对路径；
- manifest通过M1 Session Schema；
- samples逐行通过M1 Sample Schema；
- scenario和expected包含版本与限制；
- summary计数与实际文件一致；
- 默认不生成raw frames；
- 显式兼容模式才生成`raw_frames.bin`。

### 7.2 保存失败恢复

- 临时目录和最终目录命名可区分；
- 成功后原子完成；
- 失败后保留可识别证据；
- 不覆盖已有session目录；
- 同session ID冲突时失败。

### 7.3 ReplayDataSource

- 保存样本与重放样本逐条相等；
- 重放不调用模拟器RNG；
- 重放不修复异常时间戳或丢帧；
- manifest来源和配置摘要保持；
- 缺失/损坏文件明确失败；
- 未知字段或非法Schema失败。

### 7.4 CLI

至少覆盖：

```text
--list-scenarios
--scenario
--seed
--duration
--sample-rate
--output
```

断言：

- 列表包含注册表全部场景；
- 正常命令退出码0；
- 非法场景非0；
- 非法duration/sample rate非0；
- 输出摘要包含session ID、scenario、seed、样本数和目录；
- 同命令在不同目录生成相同内容摘要；
- CLI不接受任意未验证配置覆盖。

### 7.5 黄金摘要

每个核心场景摘要至少包含：

- sample count；
- first/last frame sequence；
- first/last device time；
- channel availability counts；
- clipping counts；
- device state counts；
- event codes；
- integrity counts；
- expected核心字段；
- canonical content hash。

黄金测试不提交大规模样本数据，只保存小型摘要或在测试中固定预期。

### 7.6 P1D退出门

- 所有会话文件完整；
- 保存与重放一致；
- CLI可用且错误码正确；
- 黄金摘要稳定；
- 全部18个场景通过；
- CI和D3正式验收通过。

## 8. Schema和契约测试

必须持续验证：

- M1-P0五类Schema未被静默修改；
- M1Sample未知字段失败；
- 非法枚举失败；
- 缺失必填字段失败；
- ISO-8601时间必须带时区；
- source type为simulator；
- 缺失通道使用null+status；
- manifest completion和reason跨字段一致；
- 失败会话不能analysis allowed；
- synthetic限制完整。

M1-P1输出`expected.json`和`summary.json`可使用本阶段内部Schema或严格运行时校验，但不能冒充M1QualityResult、M1Decision和M1Report正式输出。

## 9. 确定性验收

确定性分三层：

### 9.1 结构确定性

同配置：

- 样本数量；
- 字段集合；
- 事件集合；
- 文件角色一致。

### 9.2 数值确定性

同配置：

- 每条通道值；
- 时间戳；
- 状态；
- fault flag一致。

### 9.3 序列化确定性

规范化输出：

- scenario；
- expected；
- summary；
- canonical sample stream hash一致。

会话ID和输出路径如采用运行时生成值，应从内容哈希排除或允许由测试显式固定。

## 10. 性能与规模边界

M1-P1不做真实性能竞赛，但必须防止明显不可用：

- 30秒、250–500 Hz三通道场景能流式生成；
- 生成过程不将全部样本强制常驻内存；
- JSONL逐行写入；
- 测试使用短场景，避免CI过慢；
- 至少一个较长场景验证流式行为；
- 不以吞吐量宣称真实硬件能力。

性能目标在实现前不写死；验收记录实测时间和内存趋势即可。

## 11. 回归命令

每个子阶段至少运行相关专项测试和全量回归。

专项命令：

```bash
python -m pytest tests/test_m1_simulator.py -q
python -m pytest tests/test_m1_simulator_scenarios.py -q
python -m pytest tests/test_m1_simulator_sessions.py -q
python -m pytest tests/test_m1_simulator_cli.py -q
```

全量：

```bash
python -m pytest -q
python -m unittest discover -s tests -v
python scripts/generate_d3_acceptance.py
```

CI：

- Python tests and D3 acceptance；
- Web production build；
- 如增加M1-P1专项job，应避免重复安装和无必要延长CI。

## 13. 停止条件

出现以下任一情况停止后续实现：

- M1-P0字段语义不足，必须修改契约；
- 无法保证同配置确定性；
- Pulse和PPG无法共享统一BeatTimeline；
- 故障状态与数值无法保持一致；
- Replay必须重新运行模拟器才能工作；
- 需要增加重大依赖；
- D3正式验收回归失败；
- 模拟器开始承担正式质量算法或INT决策；
- 需要使用真实硬件参数才能继续。

停止时记录问题、影响和建议，不静默放宽测试。
