# M1-P3 最终验收报告（Final Review / Draft）

本文件记录 P3F Final Review 阶段的验收主张边界。Draft HEAD 证据不是 main 终证。

## 架构

P3A 会话相对 POSIX 路径与不可变 run → P3B Direct/Replay 等价与 Quality Gate → P3C 只读 API → P3D 生产 Web（无报告 UI）→ P3E 冻结 M1Report 投影。

P3F 聚合上述证据，并增加：21-attempt E2E 矩阵、验收专用 semantic golden、历史不可变、报告篡改区分、性能表征、CI 聚合门禁。

Final Review 额外约束：golden 生成必须核对真实 git HEAD；过期 P3B/C/E 产物不得充当当前 HEAD 回归；`--skip-web` 不得把 Web 写成已嵌入通过；并发门禁必须是重叠写入；性能 `NOT_COMPARABLE` 不得伪装成回归 PASS。

## 安全边界

- Frozen M1Report / schema 不变
- 正式参数 pre-H1：`null` / blocked
- P4 决策：`final_action=null`，`decision_rule_version=null`
- 始终 `not_for_medical_use`
- 无假零、无 oracle 依赖、无医学结论
- 无新增 React 报告 UI

## 已知限制

- 模拟器证据，不是真实硬件
- 性能数字是软件表征，环境不可比时记 `NOT_COMPARABLE`
- 历史 P3C `report_api_present=false` 保持阶段史；聚合验收独立断言当前 report API 存在
- 历史 P3D backend-freeze 不因 P3E 后端扩展而被改写

## 后续门禁

Implementation → Final Review → Ready → Merge Gate → exact-main 验收。

只有 exact-main `m1-p3-acceptance.json` 的 `acceptance=true` 且 `software_commit_sha` 等于实际 merge SHA 后，才可勾选 Issue #29 的 M1-P3。
