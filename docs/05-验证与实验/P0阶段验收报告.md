# P0阶段验收报告

验收对象：合成环境软件闭环；结论：通过；不包含真实硬件与人体性能。

## 1. 交付物

- P0实施总方案、需求、协议、数据与安全规范；
- 二进制协议v0与CRC32；
- 确定性脉搏和多载荷设备模拟器；
- 原始优先会话存储、Manifest、事件与重放；
- 质量门控、去基线、峰检测、心率与压力响应；
- FastAPI REST与WebSocket实时采集；
- React实时脉搏/载荷和结果页面；
- 自动化测试与30分钟连续运行。

## 2. 自动测试

- 测试数量：15；
- 结果：全部通过；
- 覆盖：协议回环、CRC损坏、尾帧、确定性、压力响应、状态、会话、重放、质量门控、API、WebSocket；
- 故障注入：CRC错误、序号缺口、时间戳回退均能统计。

## 3. 连续运行

| 指标 | 结果 |
|---|---:|
| 模拟时长 | 30分钟 |
| 采样率 | 250 Hz |
| 完整帧 | 450000 |
| 原始文件 | 23400000字节 |
| 丢帧 | 0 |
| CRC错误 | 0 |
| 重放尾部残留 | 0 |

## 4. 前端与接口

- FastAPI健康、会话模拟、会话列表和报告接口通过测试；
- WebSocket能够发送实时样本并返回完成事件；
- React/TypeScript生产构建通过；
- 页面展示实时脉搏、载荷、完整帧、丢帧、质量和模拟压力响应。

## 5. 已知限制

- 合成波不是经验证的人体血流动力学模型；
- 40/80/120为无医学单位的软件测试参数；
- P0峰检测和质量规则必须用P1真实数据重新冻结；
- 尚未实现真实串口、MCU、传感器、ADC和自动施压；
- 没有任何脉象或疾病识别能力；
- FastAPI测试依赖当前Starlette/httpx兼容层，出现弃用警告但不影响结果，后续锁定依赖版本。

## 6. 阶段结论

P0合成环境的软件闭环满足退出标准，可以进入P1传感器小批量选型和手动单点采集。P1接入真实硬件后必须重复数据完整性、信号质量、心率和长期运行验证。
