# M1-P1模拟场景与预期矩阵

版本：0.1.0；状态：设计评审中。

## 1. 目的

本文件冻结M1-P1最低场景集合、故障层次、默认参数边界、预期会话状态、后续质量类别和I1动作。

`expected.json`中的内容用于后续M1-P2、M1-P4和M1-P5测试断言，不代表M1-P1已经执行正式质量算法或决策引擎。

所有场景：

- `source_type=simulator`；
- 明确`not_hardware_validated`；
- 真实阈值保持`pending_h1_calibration`；
- 不产生疾病、脉象或医疗结论。

## 2. 场景定义结构

每个`ScenarioDefinition`至少包含：

```text
scenario_id
scenario_version
description
default_duration_s
default_sample_rate_hz
default_seed
enabled_channels
physiology_config
fault_schedule
expected_quality_label
expected_reason_codes
expected_int_action
analysis_allowed
expected_completion
multi_attempt_plan
```

默认采样率和持续时间只是模拟软件基线，不是H1真实参数结论。

## 3. 质量和动作预期枚举

## 5. 正常场景

## 5.1 normal_high_quality

实现状态：**M1-P1A已实现**（仅数据源输出；`expected.json`会话产物仍待P1D）。

目标：提供后续SP、APP和INT的正向黄金输入。

默认：

- 三通道启用；
- 心搏事件稳定且带轻微受控间期变化；
- Pulse幅值处于模拟器内部正常范围；
- Load已建立接触并保持小幅稳定波动；
- PPG共享BeatTimeline并带固定模拟时延；
- 帧连续、时间戳单调；
- 无故障、无削顶、无断线。

预期：

- quality：`acceptable`；
- reasons：空；
- action：`accept`；
- analysis_allowed：true；
- session completed：true。

不变量：改变seed只能改变噪声细节和允许的轻微间期变化，不能引入削顶、断线或丢帧。

## 6. 信号与接触异常

本节9个场景实现状态：**M1-P1B已实现**（输出正式`M1Sample`；不生成质量分、Decision、`expected.json`或会话目录）。

默认故障窗口：会话时长的`[25%, 75%)`。`insufficient_duration`无FaultWindow。

P1C场景（`frame_loss`、`timestamp_regression`、`sensor_disconnection`、`abort`、`device_fault`、`raw_persistence_failure`、`retry_improves`、`retry_still_fails`）仍未实现。

## 6.1 weak_signal

实现状态：**M1-P1B已实现**。

注入层：Pulse通道观测层。

行为：

- 保留BeatTimeline；
- 降低Pulse观测幅值（合成参数`pulse_amplitude_scale`，非H1阈值）；
- Load保持接触；
- PPG保持参考可用；
- sensor status保持connected；
- 不使用`null`伪装弱信号。

预期：

- quality：`weak_signal`；
- reason：`LOW_PULSE_AMPLITUDE`；
- action：`retry_same_position`；
- analysis_allowed：false；
- completed：true。

## 6.2 no_contact

实现状态：**M1-P1B已实现**。

注入层：接触语义（FaultWindow），不扩展`SensorStatus`。

行为：

- Pulse/Load/PPG均保持`connected`（探头未接触 ≠ 传感器断线）；
- Load处于近零接触基线；
- Pulse逼近基线、无有效脉动成分，值仍为整数非`null`；
- 不使用`disconnected`/`read_failed`，也不用0表示字段缺失；
- PPG保持正常参考，用于区分“参考在、探头未接触”。

预期：

- quality：`no_contact`；
- reason：`NO_PROBE_CONTACT`；
- action：`reposition`；
- analysis_allowed：false；
- completed：true。

## 6.3 upper_saturation

实现状态：**M1-P1B已实现**。

注入层：Pulse通道。

行为：

- 指定区间内Pulse达到合成上限`synthetic_upper_limit_raw`；
- `clipping=upper`；
- 数值与flag一致；
- 窗口外恢复`clipping=none`；
- 不写真实ADC位宽结论；P1B不写`events.jsonl`。

预期：

- quality：`saturated`；
- reason：`UPPER_SATURATION`；
- action：`stop`；
- analysis_allowed：false。

## 6.4 lower_saturation

实现状态：**M1-P1B已实现**。

与上削顶对称：

- 达到`synthetic_lower_limit_raw`；
- `clipping=lower`；
- reason：`LOWER_SATURATION`；
- action：`stop`。

## 6.5 baseline_drift

实现状态：**M1-P1B已实现**。

注入层：Pulse通道。

行为：

- 使用可配置、连续、确定性的漂移函数；
- 不改变采样时刻或BeatTimeline；
- 记录漂移区间和参数；
- 不把真实传感器漂移量写成模拟结论。

预期：

- quality：`unstable_baseline`；
- reason：`BASELINE_DRIFT`；
- action：`retry_same_position`；
- analysis_allowed：false。

## 6.6 motion_artifact

实现状态：**M1-P1B已实现**。

注入层：通道观测。

行为：

- 指定区间向Pulse加入瞬态或短时宽带扰动；
- 默认可同时影响Load；
- 是否影响PPG由场景定义明确；
- 事件中记录受影响通道。

预期：

- quality：`motion_artifact`；
- reason：`MOTION_ARTIFACT`；
- action：`retry_same_position`；
- analysis_allowed：false。

## 6.7 unstable_load

实现状态：**M1-P1B已实现**。

注入层：Load通道，可配置耦合Pulse。

行为：

- Load在接触状态下出现明显不稳定波动；
- Pulse可按显式配置出现幅值调制；
- 不模拟未经验证的人体压力响应规律；
- 设备状态仍可为正常。

预期：

- quality：`manual_review_required`；
- reason：`UNSTABLE_CONTACT_LOAD`；
- action：`manual_review`；
- analysis_allowed：false。

## 6.8 ppg_misalignment

实现状态：**M1-P1B已实现**。

注入层：PPG观测时间关系。

行为：

- BeatTimeline不变；
- PPG相对事件增加超出正常模拟范围的时延或错位；
- Pulse保持正常；
- PPG status仍connected，区分错位和断线。

预期：

- quality：`reference_mismatch`；
- reason：`PPG_ALIGNMENT_MISMATCH`；
- action：`manual_review`；
- analysis_allowed：false。

## 6.9 insufficient_duration

实现状态：**M1-P1B已实现**。

注入层：会话配置（短`duration_s`，无FaultWindow）。

行为：

- 三通道保持normal语义；
- 默认短时长为合成测试基线，不是临床有效窗口阈值；
- 设备和传输无故障；
- 数据源正常结束。

预期：

- quality：`insufficient_duration`；
- reason：`INSUFFICIENT_VALID_DURATION`；
- action：`retry_same_position`；
- analysis_allowed：false；
- completed：true。

## 7. 设备、传输和存储异常

本节及第8节多attempt场景实现状态：**M1-P1C已实现**（内存证据与`M1Sample`输出；无正式会话文件）。

## 7.1 frame_loss

实现状态：**M1-P1C已实现**。

注入层：传输层。

首版语义：模拟发送端生成连续内部样本，但输出适配层丢弃指定帧，保留后续原始`frame_sequence`，使接收端看到序号缺口。

行为：

- 不重新编号；
- `events.jsonl`记录丢弃范围；
- manifest完整性摘要记录missing frames；
- BeatTimeline和基础通道不回写。

预期：

- quality：`data_integrity_failure`；
- reason：`FRAME_SEQUENCE_GAP`；
- action：`stop`；
- analysis_allowed：false；
- completed：false。

## 7.2 timestamp_regression

实现状态：**M1-P1C已实现**。

注入层：传输时间。

行为：

- frame sequence连续、不丢帧；
- 指定帧`device_time_us`回退且`timestamp_valid=false`；
- `host_received_at_utc`保持单调；
- 三通道值不变；
- 内存事件记录回退前后时间（不写`events.jsonl`）。

预期：

- quality：`data_integrity_failure`；
- reason：`TIMESTAMP_REGRESSION`；
- action：`stop`；
- completed：false。

## 7.3 sensor_disconnection

实现状态：**M1-P1C已实现**。

注入层：设备状态（区别于P1B `no_contact`）。

行为：

- 默认Pulse `status=disconnected`、`value=null`、`clipping=none`；
- `device_state=FAULT`，`fault_flags`含`sensor_disconnected`；
- 触发样本后结束输出；
- ReceiveIntegrity保持true。

预期：

- quality：`data_integrity_failure`；
- reason：`SENSOR_DISCONNECTED`；
- action：`stop`；
- completed：false。

## 7.4 abort

实现状态：**M1-P1C已实现**。

注入层：设备安全状态。

行为：

- 触发帧`device_state=SAFE_HOLD`；
- `fault_flags`含`emergency_stop`；
- 触发后立即停止，无后续ACQUIRE；
- 不模拟真实电机回撤。

预期：

- quality：`data_integrity_failure`；
- reason：`EMERGENCY_STOP`；
- action：`abort_and_release`；
- analysis_allowed：false；
- completed：false。

## 7.5 device_fault

实现状态：**M1-P1C已实现**。

注入层：设备状态。

行为：

- 使用Schema已有flag（默认`buffer_overflow`）；
- `device_state=FAULT`；
- 触发后停止；
- 与普通质量差区分。

预期：

- quality：`data_integrity_failure`；
- reason：`DEVICE_FAULT`；
- action：`abort_and_release`；
- completed：false。

## 7.6 raw_persistence_failure

实现状态：**M1-P1C已实现**（内存CaptureRunner；无正式SessionRecorder文件）。

注入层：CaptureRunner / FailingSampleSink。

行为：

- 成功写入N条后确定性失败；
- 不写真实磁盘；
- 已写入样本计数保留；
- `raw_persistence_status=failed`，`completed=false`。

预期：

- quality：`data_integrity_failure`；
- reason：`RAW_PERSISTENCE_FAILURE`；
- action：`stop`；
- analysis_allowed：false；
- completed：false。

## 8. 多attempt场景

实现状态：**M1-P1C已实现**（固定计划；不执行INT；无正式会话目录）。

说明：单次attempt数据源可正常结束；计划级`expected_completion`表示整组目标是否成功。P1D再表达attempt级与计划级文件状态。

## 8.1 retry_improves

实现状态：**M1-P1C已实现**。

结构：

```text
sequence_id
├─ attempt-1: weak_signal
└─ attempt-2: normal_high_quality或明确改善
```

要求：

- attempt具有独立session_id；
- 共享sequence_id和位置条件；
- attempt_index从1开始；
- 每次配置、输出和预期独立保存；
- 最终sequence摘要记录改善。

预期：

- attempt 1：`weak_signal` / `retry_same_position` / analysis false；
- attempt 2：`acceptable` / `accept` / analysis true；
- sequence最终状态：accepted。

## 8.2 retry_still_fails

实现状态：**M1-P1C已实现**。

结构：

```text
sequence_id
├─ attempt-1: weak_signal
├─ attempt-2: weak_signal
└─ attempt-3: weak_signal，达到模拟预设上限
```

M1-P1只生成有限attempt，不执行规则循环。

预期：

- 前两次：`retry_same_position`；
- 最后一次：`reposition`；
- sequence最终analysis_allowed：false；
- 不允许无限生成。

真实最大重采次数仍为`pending_h1_calibration`；这里的attempt数只用于软件流程测试。

## 9. 故障组合规则

首版原则：

- 每个单故障场景只验证一个主要未知量；
- `retry_*`是显式多会话组合；
- 不默认开放任意故障组合；
- 后续需要组合场景时必须注册新场景ID或明确组合版本；
- 冲突故障配置在启动前失败。

固定优先级：

```text
安全设备状态
→ 存储失败
→ 传输完整性
→ 传感器连接
→ 通道削顶/伪影/漂移
→ 会话时长
```

优先级只决定预期主原因和会话状态，不删除次级事件证据。

## 11. 场景评审清单

- [ ] 所有场景ID唯一；
- [ ] 场景版本明确；
- [ ] 每个场景只有一个主要未知量；
- [ ] 数值、status、flag、事件和manifest一致；
- [ ] 所有故障有明确开始和结束，瞬时事件除外；
- [ ] 不同seed不改变核心语义；
