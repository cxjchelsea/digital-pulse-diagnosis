# M1-P3测试与验收计划

版本：0.1.0-design；状态：方案冻结候选，尚未实现P3测试或验收代码。

Baseline：`main@5a924289e912f60c448a399c01d3bf7dd916d505`。

## 1. 验收目标

M1-P3验收证明：

- APP只消费冻结M1 session/raw和SP结果，不重新实现SP或读取模拟oracle；
- raw persistence、session completion、integrity和quality gate均fail closed；
- session、SP、APP和report资产可校验、可追溯、可复制重放；
- Direct和Replay产生相同APP/report语义内容；
- blocked/partial/corrupt session可显示事实，但不能产出正式参数；
- 历史分析结果不被重放静默覆盖；
- M1Report合法且始终保留非医疗用途限制；
- D3、M1-P1、M1-P2和Web无回归。

验收不证明真实硬件性能、真实H1标定、医学有效性、P4决策、M1-PV或M1完成。

## 4. P3A contracts / persistence矩阵

### 4.1 APP模型

- frozen dataclass/Pydantic边界；
- app processing version与schema version分离；
- run/file role唯一；
- hash必须为64位小写hex；
- `analysis_allowed=false`时formal parameters为null；
- limitation必须包含`not_for_medical_use`；
- stable canonical serialization。

### 4.2 原子持久化

- asset全部写完后才提交run目录；
- checksums在run内最后写；
- APP manifest全局最后更新；
- 每个写入点注入失败后manifest不得标complete；
- `.tmp`不被列表/读取接口识别；
- 已有run不可覆盖；
- 完全相同的run可幂等返回；
- 同run id但内容不同必须`artifact_conflict`。

### 4.3 路径和完整性

- session-relative POSIX路径通过；
- `../x`、绝对路径、Windows drive、UNC、反斜杠逃逸拒绝；
- symlink/junction逃逸拒绝；
- duplicate role拒绝；
- missing、size mismatch和SHA mismatch拒绝；
- 非法JSON、超大line/array shape受控失败。

### 4.4 Source checksum assurance

- Direct session复用Recorder实际sample/event hash；
- 既有P1 session首次注册生成registration snapshot；
- 注册后篡改raw必被检测；
- registration snapshot不得被描述为采集时硬件签名或历史防篡改证明；
- future acquisition-seal checksum与app-registration来源在provenance中可区分；
- source checksum登记不改写P0 `M1Session`或Schema。

## 5. P3B Replay / projection / gate矩阵

### 5.1 Source abstraction

- Simulator/Replay adapter返回统一接口；
- acquisition source保持原值；
- execution mode单独记录；
- future hardware fake adapter无需改变APP pipeline；
- production pipeline不存在scenario ID分支。

### 5.2 SP projection

- APP projection不修改输入`SPProcessingResult`；
- raw/causal/offline/PPG序列明确分离；
- window/beat/reference ID保持；
- quality label/reason/metrics逐字段来自SP；
- integrity与quality分栏；
- APP持久化前后SP `result_sha256`不变；
- P2字段新增时contract gate要求明确映射/排除，不静默遗漏。

### 5.3 Quality Gate truth table

| Session/raw/SP事实 | analysis_allowed | formal parameters |
|---|---:|---|
| complete + raw ok + SP evaluated + all acceptable | true | available，带synthetic/pending状态 |
| incomplete/partial | false | null/unavailable |
| raw failed/not_started | false | null/unavailable |
| raw missing/corrupt/checksum mismatch | false | null/unavailable |
| SP blocked_before_quality | false | null/unavailable |
| SP blocking_codes非空 | false | null/unavailable |
| quality results为空 | false | null/unavailable |
| 任一formal window非acceptable | false | null/unavailable |
| provenance/config缺失 | false | null/unavailable |

对每个false分支验证raw/diagnostic view仍可按可用事实打开，failure reasons稳定排序。

## 6. P3C API矩阵

- session list分页、过滤、稳定排序；
- session detail不泄露绝对路径；
- channels范围、max_points和display_downsampled元数据；
- analysis/report/history读取正确run；
- replay默认不产生文件；
- `persist=true`只新增run；
- 404/400/409/422/500映射到稳定error code；
- Python exception和stack不进入响应；
- session ID/path注入被拒绝；
- invalid/corrupt session在列表可见但formal endpoint fail closed；
- subject/operator敏感字段默认不在列表响应。

- display downsampling不改变分析摘要。

## 8. P3E Report矩阵

### 8.1 M1Report Schema

每个报告必须：

- `M1Report.validate_schema()`通过；
- source/session与manifest一致；
- `analysis_allowed`等于唯一Quality Gate结果；
- blocked时`objective_parameters is None`或空且无非null值；
- `failure_summary`解释阻断事实；
- `decision_summary`不伪造P4决策；
- simulation包含`synthetic_input`；
- 始终包含`not_for_medical_use`。

### 8.2 Determinism

同一输入重复运行验证：

- APP fingerprint相同；
- gate decision/reasons相同；
- report semantic fingerprint相同；
- APP/report SHA相同；
- generated time变化不影响semantic hash；
- run路径/UI viewport变化不影响semantic hash；
- serialization不产生NaN/Infinity。

## 10. Multiattempt

### retry_improves

每个attempt独立形成APP view：第一次blocked，第二次acceptable。P3不合并成`accept`决策，不自动选择attempt，不覆盖第一次artifact。

### retry_still_fails

三个attempt均保留且blocked。P3不产生retry count、stop或reposition动作；这些属于P4。

## 11. Raw persistence failure硬门

对`raw_persistence_failure`必须同时断言：

```text
session listed = true
diagnostic detail accessible = true
raw status = failed
analysis_allowed = false
formal parameters = null/unavailable
report status = failed or incomplete by frozen mapping
failure contains persistence fact
no committed complete APP run from incomplete write
```

## 12. Replay损坏与安全矩阵

分别执行：

- 删除raw asset；
- 篡改raw字节；
- 修改manifest中的文件引用；
- 修改APP checksum；
- 填入`../../secret`；
- absolute/drive/UNC路径；
- session-root内symlink指向外部；
- duplicate file role；
- JSONL中插入非法JSON、错误session ID或超限数组。

全部必须fail closed，且不得提交新的complete run或改变历史artifact。

## 13. Oracle isolation

对代表性及正式矩阵执行：

```text
baseline session → Replay + SP + APP
delete scenario.json / expected.json → rerun
tamper expected quality/action → rerun
```

要求SP result SHA、APP semantic SHA、gate和report semantic SHA全部不变。生产代码import graph不得依赖`ScenarioDefinition.expected_*`。

## 14. Direct / Replay等价

至少比较：

```text
Direct: Simulator → session/raw verified → SP → APP
Replay: persisted raw → ReplayDataSource → SP → APP
```

逐字段比较：

- SP `result_sha256`；
- quality/windows/beats/reference/integrity投影；
- gate decision/reasons；
- formal parameter availability/value；
- APP semantic fingerprint；
- report semantic fingerprint。

排除run path、generated time和execution mode等明示非语义provenance字段。

## 15. 历史run不可变

- commit A产生run A；
- commit B只读Replay不修改A的任何mtime/bytes/manifest entry；
- commit B持久化时新增run B；
- current pointer变化不删除A；
- stored vs replayed显示A/B软件SHA、APP/SP版本和所有hash；
- 读取页面不会产生run或更新current pointer。

## 16. 性能预算

记录但暂不声明真实设备实时能力：

- 8秒和60秒@250Hz会话的load/SP/project/report耗时；
- peak memory；
- raw JSONL streaming吞吐；
- channel API生成5000显示点耗时；
- Web渲染大viewport的基本交互可用性。

阈值应宽松，用于发现数量级回归。性能失败不得通过降低分析采样率或把display downsampling混入分析解决。

## 22. 停止条件

出现以下任一情况停止并单独报告：

- APP必须修改P0/P2才能实现；
- 生产APP需要scenario oracle才能通过；
- raw/quality gate可以被API/UI绕过；
- unavailable被编码为0或伪值；
- Replay覆盖历史artifact；
- path/symlink可逃逸session root；
- checksum篡改未被发现；
- Direct/Replay semantic不一致；
- APP或report出现医学结论、真实校准声称或P4动作；
- D3/P1/P2任一回归；
- 未经评审引入大型依赖/框架迁移。
