# D3 设备侧安全监督与状态机设计

## 1. 实施范围

D3-D 在 D3-B 被控对象和 D3-C 控制器之上实现设备侧安全裁决与确定性状态机。所有阈值均为仿真相对单位，不是人体安全限值。

本工作包负责：

- 每个控制 tick 检查安全输入和命令权限；
- 同 tick 多故障按 D3-A 冻结优先级裁决；
- 普通流程、ABORT、主机失联和故障抢占；
- 急停、关键通道失效、卡滞、看门狗的零输出和故障锁存；
- 显式 RESET 后重新 SELF_TEST；
- 生成不可变安全事件。

故障注入矩阵、检测延迟统计和完整场景回归属于 D3-E。

## 2. 模块边界

`D3StateMachine → D3SafetySupervisor → 最终电机命令`

安全监督器不依赖 API、Web 或 D2 分析模块。上位机只能请求 START、ABORT、RESET，不能直接清除锁存故障或绕过安全裁决。

## 3. 普通状态路径

```text
BOOT → SELF_TEST → IDLE → APPROACH → CONTACT
→ STABILIZE → ACQUIRE → STEP/STABILIZE
→ RETRACT → IDLE
```

- ACQUIRE 稳态失效时返回 STABILIZE；
- 多目标采集通过 STEP 切换目标；
- 最后一个目标完成后由设备侧进入 RETRACT；
- RETRACT 到达下限位后回到 IDLE。

## 4. 安全抢占

- 急停：立即命令归零并进入 FAULT_LATCHED，不承诺主动退回；
- 非有限数值、限位冲突、位置通道失效、电机卡滞、看门狗失败：归零并锁存；
- 硬超限、上限位、载荷通道失效：位置通道有效时受控 RETRACT，否则锁存；
- 主机失联、状态超时、无法稳定：由设备侧 RETRACT；
- 数据质量失败：正式窗口失效并返回 STABILIZE；
- 同 tick 多故障：事件记录全部检测结果，只执行优先级最高的动作。

安全抢占可以覆盖普通状态边，因为安全故障不能等待业务路径许可。

## 5. 命令不变量

- 非 APPROACH/STABILIZE/ACQUIRE/STEP 状态禁止正向命令；
- RETRACT 只允许负向命令；
- 上限位禁止正向、下限位禁止负向；
- 急停或载荷传感器无效时禁止正向；
- 达到模型软载荷或最大压缩速率时立即阻断正向；
- 所有命令最终限制在 `[-1, 1]`；
- FAULT_LATCHED 中任何 START 均无效。

## 6. 复位语义

FAULT_LATCHED 只能通过显式 RESET 离开，并且必须同时满足：

1. 急停已清除；
2. 载荷和位置通道有效；
3. 看门狗正常。

RESET 的目标是 SELF_TEST，不是 IDLE。只有自检通过后才能重新进入 IDLE。

```bash
python -m pytest tests/test_d3_safety.py tests/test_d3_state_machine.py -q
python -m pytest -q
```

专项测试覆盖命令权限、软硬阈值、变化率、限位、急停、多故障优先级、传感器、卡滞、看门狗、主机超时、ABORT、锁存、复位、自检、正常 Profile 和确定性时基。
