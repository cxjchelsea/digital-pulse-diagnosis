# D3 故障注入矩阵与安全回归设计

## 1. 目标与边界

D3-E 将 D3-D 的单项安全规则组织成固定时基、可批量运行、可确定性重放的故障矩阵。它验证定义模型中的检测、优先级、动作和目标状态，不证明真实传感器诊断覆盖率、执行器释放能力或人体安全。

## 2. 默认矩阵

默认覆盖 14 类输入：

1. 急停；
2. 非有限数值；
3. 载荷硬超限；
4. 上下限位冲突；
5. 上限位；
6. 下限位异常；
7. 载荷传感器无效；
8. 位置传感器无效；
9. 电机卡滞；
10. 看门狗超时；
11. 主机心跳超时；
12. 状态超时；
13. 无法稳定；
14. 数据质量失败。

每个矩阵项冻结注入时间、持续时间、请求命令、预期主故障、预期安全动作和预期状态。

## 3. 时间与注入语义

- 使用 `TimingConfig.control_period_us`，不读取墙钟时间；
- `at_s` 转换为离散控制 tick；
- `duration_s=0` 表示单 tick 脉冲；
- 正持续时间采用半开区间 `[at_s, at_s + duration_s)`；
- 相同配置和输入必须产生相同结果对象；
- 检测延迟以控制 tick 记录，默认要求注入后一个 tick 内完成裁决。

## 4. 多故障裁决

同一 tick 可注入多个故障。安全监督器记录全部检测码，但只按 D3-A 冻结优先级执行一个主动作。例如急停、硬超限和限位冲突同时发生时：

- 主故障必须是急停；
- 命令必须为零；
- 目标状态必须为 `FAULT_LATCHED`；
- 检测集合仍须包含硬超限和限位冲突。

## 5. 通过条件

每个矩阵项必须同时满足：

- 实际主故障等于预期故障；
- 实际动作等于预期动作；
- 实际状态等于预期状态；
- 检测延迟不超过一个控制 tick；
- 安全类故障检测时命令不得继续加压；
- 数据质量失败只使采集窗口失效，不伪装为硬安全故障。

## 6. 验收

```bash
python -m pytest tests/test_d3_fault_matrix.py -q
python -m pytest -q
```

专项测试还覆盖矩阵完整性、ID 唯一性、延迟注入、脉冲/持续故障、自定义心跳阈值、同 tick 优先级和确定性重放。

D3-E 完成后，故障矩阵结果可以被 D3-F 报告/API/Web 使用，但当前阶段不写会话目录或报告哈希。
