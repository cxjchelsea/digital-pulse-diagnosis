# 项目总体方案

## 1. 背景与适用性

项目发起人具备控制科学、机器学习、Python/Java/TypeScript、FastAPI、React、医疗AI系统和工业数据建模经验，但嵌入式与电子硬件经验接近零。因此路线设计遵循以下约束：

- 先利用已有软件与算法能力建立可测试的数据闭环；
- 不同时学习定制PCB、柔性材料、气动系统和深度学习；
- 优先采用开发板、成熟传感器与标准机械件；
- 每一阶段只有一个主要未知量；
- 用实验指标决定是否升级，不以“组装完成”作为成功标准；
- 先解决采集可靠性，再研究脉象和诊断。

项目对个人开发者最有价值的成果不是复刻已有脉诊仪，而是形成一套可解释、可验证的自适应采集方法，并保留从原始信号到报告的完整证据链。

## 2. 问题定义

### 2.1 核心问题

在不同手腕尺寸、桡动脉位置、软组织厚度和佩戴状态下，怎样自动或半自动找到有效采集位置，并在已知接触压力下获得稳定、重复的桡动脉脉搏波？

### 2.2 首期研究假设

1. 同步记录动态脉搏信号和静态接触力，比只记录单条波形具有更好的可解释性；
2. 对压力进行分层扫描，可以找到个体化的有效压力区间；
3. 信号质量评分可以减少无效数据进入后续模型；
4. 多点空间采样可降低人工定位依赖；
5. 只有完成重复性验证后，脉象标签研究才有意义。

这些是假设，不是结论，必须通过实验验证。

## 3. 产品分层

| 层级 | 输入 | 输出 | 本项目策略 |
|---|---|---|---|
| 采集层 | 手腕、位置、压力 | 原始脉搏与载荷数据 | 优先完成 |
| 质量层 | 原始信号、设备状态 | 有效/无效、异常原因 | 优先完成 |
| 参数层 | 有效脉搏波 | 心率、节律、形态、压力响应 | MVP范围 |
| 脉象层 | 多压力、多位置波形 | 浮沉迟数等候选标签 | 后续研究 |
| 临床层 | 脉象、症状、检查 | 证候或疾病辅助判断 | 不属于早期范围 |

## 4. MVP范围

### 4.1 必须实现

- 桌面式手腕托架和可更换单探头；
- 手动粗定位关部；
- 动态脉搏与静态接触力同步采样；
- 原始数据不丢失地发送到电脑；
- 实时显示波形、接触力与设备状态；
- 自动执行多个压力平台的采集流程；
- 基线漂移处理、逐搏切分、心率和质量评分；
- 会话级元数据与原始数据可追溯保存；
- 安全限位、急停/释放、故障状态机；
- 重复采集与参考心率对比实验。

### 4.2 明确不做

- 第一版不做六部寸关尺全覆盖；
- 不自研柔性传感材料；
- 不直接制作可穿戴腕带；
- 不用大语言模型处理原始波形；
- 不输出疾病诊断和治疗建议；
- 不把单个受试者数据随机切分后宣称高准确率；
- 不在采集可靠性未知时训练复杂深度学习模型；
- 不把厂家宣传参数当作本项目实测性能。

## 5. 用户与使用场景

### 5.1 首期用户

- 项目开发者；
- 参与工程验证的健康成年人；
- 后期参与标注和方法评审的中医师；
- 面试或作品评审者。

### 5.2 首期工作流

1. 创建匿名受试者与采集会话；
2. 受试者静坐并将前臂放入托架；
3. 操作者手动粗定位关部；
4. 设备低速接近并检测初始接触；
5. 按压力平台依次稳定、采集和退回；
6. 软件实时判断信号质量，必要时提示重试；
7. 保存原始信号、校准、压力、状态与元数据；
8. 生成客观参数和实验摘要；
9. 不产生疾病结论。

## 6. 工作包

### WP0：需求、风险与实验规范

产物：

- 系统需求规格；
- 风险清单；
- 统一的名词、单位和坐标定义；
- 人体实验安全检查表；
- 数据字典；
- 阶段验收表。

### WP1：设备与信号模拟器

产物：

- 可配置心率、形态、漂移、噪声、运动伪影；
- 可模拟压力平台和设备状态；
- 与未来固件一致的通信协议；
- 支持实时发送和离线回放；
- 黄金样本与自动化测试。

目的：在硬件到货前完成上位机、协议解析和基础算法。

### WP2：手动单点采集

产物：

- 两至四类候选传感器对比；
- 面包板/模块化模拟前端；
- MCU定时采样；
- USB串口传输；
- 三种探头接触结构；
- PPG或其他参考心率同步。

阶段门：在多次拆装后仍能获得不削顶、周期清晰且心率合理的波形。

### WP3：接触力与压力响应

产物：

- 独立静态载荷通道；
- 载荷标定曲线；
- 多压力手动采集协议；
- 压力—幅值/质量响应图；
- 最佳压力区间定义方法。

阶段门：同一人在同日重复采集可形成相近的压力响应趋势。

### WP4：自动施压

产物：

- 步进电机、丝杆、限位和探头机构；
- 接触检测；
- 压力闭环控制；
- 平台稳定判据；
- 超限、失联、卡滞和急停处理；
- 自动退回。

阶段门：在仿体和人体安全测试中满足冻结后的压力稳态误差、超调和释放时间要求。

### WP5：自动寻脉

产物：

- 横向多点阵列或机械扫描结构；
- 空间信号质量图；
- 桡动脉中心候选；
- 自动选点与失败回退；
- 与人工定位对照实验。

阶段门：在不同腕围和重复佩戴情况下达到预设有效信号获取率。

### WP6：AI脉象研究

前提：

- 固定硬件版本与采集协议；
- 有中医师合作；
- 有标签定义和分歧处理；
- 数据按受试者隔离；
- 有足够样本量和外部测试设计。

先后顺序：

1. 信号质量分类；
2. 客观参数估计；
3. 浮/沉、迟/数等相对客观标签；
4. 多标签传统机器学习基线；
5. 数据量充分后才评估1D-CNN/TCN/Transformer；
6. LLM仅用于结构化结果的自然语言解释。

## 7. 技术路线选择

### MCU

首版选择ESP32-S3开发板的理由：

- 成本低、资料多、USB和通信方便；
- 足以承担数百Hz的多通道采样和状态控制；
- 适合嵌入式入门与快速迭代。

若后续出现ADC接口、实时确定性、低功耗或医疗级硬件设计要求，再评估STM32。不要为了“更专业”提前换平台。

### 执行机构

首版采用电机＋丝杆桌面机构：

- 控制和调试直观；
- 易于加入机械限位；
- 不受腕带体积限制；
- 方便更换传感器和探头。

气囊适合后续可穿戴版本，但早期会引入气泵、阀、气密性、滞后和噪声等额外变量。

### AI

先建立可解释基线：

- 规则和阈值；
- Logistic Regression；
- Random Forest；
- XGBoost；
- 校准后的概率与不确定性。

模型必须报告按受试者隔离的结果，并与简单基线比较。

## 8. 数据策略

### 8.1 数据层级

- L0：ADC原始计数和完整设备状态，不可覆盖；
- L1：工程单位换算后的脉搏、载荷和位置；
- L2：滤波、质量掩码和逐搏切分；
- L3：特征与模型输入；
- L4：模型输出、解释和人工标注。

每个派生层都要记录算法版本和上游数据标识。

### 8.2 数据拆分

- 同一受试者的所有会话只能属于训练、验证或测试中的一个集合；
- 传感器选型和阈值调试使用开发集，冻结后才运行测试集；
- 后期尽量保留不同时间、设备和操作者的外部测试；
- 不以窗口数量冒充受试者数量。

## 9. 初始验收指标

以下是需要在P1/P2实测后冻结的工程目标，不是已实现结果。

| 指标 | 初始目标 | 说明 |
|---|---:|---|
| 原始采样率 | 250–500 Hz | 以有效带宽和噪声实测决定 |
| 连续采集丢帧率 | <0.1% | 包含帧序号检查 |
| 心率平均绝对误差 | ≤2 bpm | 与同步参考设备比较 |
| 压力平台稳态误差 | ≤目标值的5% | P3冻结 |
| 压力超调 | ≤10% | 与安全上限分开 |
| 自动释放时间 | ≤2 s | 故障触发到卸载 |
| 有效信号获取率 | ≥90% | 定义有效判据后使用 |
| 同次重测关键特征CV | ≤15% | 先报告分指标结果 |
| 自动寻脉成功率 | ≥85% | P5目标，失败必须可检测 |

若实测显示目标不合理，应通过决策记录调整，不能事后选择性报告。

## 10. 风险

| 风险 | 后果 | 应对 |
|---|---|---|
| 传感器漂移/迟滞 | 压力响应不可重复 | 多型号对照、标定、预热和温漂记录 |
| 电机振动污染信号 | 平台波形失真 | 到位后停机稳定再采样、机械隔振 |
| 单一传感器同时测静态与动态不足 | 动态信号被大静载荷淹没 | 静态载荷与动态脉搏分通道 |
| 手腕定位差异 | 重测差 | 托架、标记、阵列/扫描寻脉 |
| 数据泄漏 | AI指标虚高 | 受试者级拆分、冻结测试集 |
| 医生标签不一致 | 模型学习主观偏差 | 多专家、置信度、分歧建模 |
| 过早医疗宣称 | 安全与合规风险 | 限定为研究原型和客观参数 |
| 项目范围过大 | 长期不能交付 | 阶段门、MVP非目标、每阶段演示 |

## 11. 预期简历证据

项目最终应积累以下证据，而不只是产品照片：

- 系统框图、原理图、PCB/CAD版本；
- 固件定时采样、缓冲和故障状态机；
- 协议定义及丢帧测试；
- 压力闭环阶跃响应；
- 与参考设备同步对照；
- 多人、重复佩戴实验；
- 失败样本和原因分类；
- 自动化测试和版本化数据；
- 演示视频；
- 真实量化指标。

只有在取得实测结果后，才能把对应数字写入简历。
