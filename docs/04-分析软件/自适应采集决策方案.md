# 自适应采集决策方案

版本：0.1.0；状态：M1-I1设计基线。

> **M1-P4 标注（不改写下文历史正文）：** I0–I5 成熟度路线仍有效。I1 运行时语义、reason 投影、`max_retry_count=2`、RetryScope、存储与覆盖模型以《M1 INT-I1-pre架构与规则语义设计》为准。下文输出表中的 `hold` / `adjust_pressure` / `continue_scan` 对 I1 **OUT OF SCOPE**；示例 `reason_codes`（如 `INSUFFICIENT_VALID_DURATION`）与示例 JSON 字段为 **SUPERSEDED / HISTORICAL EXAMPLE**，不得作为 `M1Decision` 运行时枚举。禁止用 LLM 做权威决策的约束仍然有效。

## 1. 定位

自适应采集决策主线记为INT。它不是第四个物理系统层，而是跨越采集硬件、信号处理和分析软件的决策控制平面。

INT回答：

> 在当前安全状态、数据完整性、信号质量和历史采集结果下，系统下一步应该继续、接受、重采、调压、换位、停止还是请求人工复核？

INT不直接替代：

- 设备侧安全状态机；
- 信号处理算法；
- 人工急停和操作者判断；
- 医疗诊断或治疗决策。

首版INT优先使用规则、状态机、可解释统计和显式阈值。只有真实数据充分且简单基线稳定后，才评估机器学习策略。

## 2. 决策优先级

所有决策遵循固定优先级：

1. **安全**：硬超限、急停、传感器失效、设备故障和人工停止；
2. **数据完整性**：CRC、序号、时间戳、断线、会话异常和原始落盘失败；
3. **信号可信度**：削顶、弱信号、运动伪影、基线不稳和逐搏不可靠；
4. **实验目标**：是否已获得足够的有效窗口、压力区间或位置证据；
5. **效率**：在不牺牲安全和可信度的情况下减少无效重采。

低优先级决策不得覆盖高优先级状态。例如，即使当前波形质量高，只要设备处于故障或ABORT状态，也必须停止并卸载。

## 3. 输入

INT只读取结构化状态，不直接从未经处理的原始波形生成决策。

### 3.1 设备与安全输入

- 设备状态机状态；
- ABORT、急停、限位、看门狗和故障标志；
- 当前目标载荷、实际载荷和执行器状态；
- 传感器连接状态；
- 原始数据落盘状态。

### 3.2 数据完整性输入

- CRC错误；
- 序号跳变和丢帧；
- 时间戳单调性和抖动；
- 缓冲区溢出；
- 会话是否正常开始和结束。

### 3.3 信号处理输入

- 质量类别与置信度；
- 有效窗口时长；
- 削顶比例；
- 基线漂移；
- 逐搏检测数量和一致性；
- 与PPG的匹配情况；
- 压力响应或空间质量特征；
- 处理版本和参数版本。

### 3.4 历史与实验输入

- 当前会话已重采次数；
- 同一位置和压力的历史结果；
- 已完成的压力平台或位置；
- 之前动作及其效果；
- 操作者确认和人工备注；
- 当前里程碑的退出条件。

## 4. 输出动作

基础动作集合：

| 动作 | 含义 |
|---|---|
| `accept` | 当前记录满足阶段质量门，纳入正式分析 |
| `retry_same_position` | 同一位置、相同条件重新采集 |
| `reposition` | 提示操作者重新定位探头 |
| `adjust_pressure` | 在允许阶段和安全边界内调整目标压力 |
| `continue_scan` | 继续下一压力或下一位置 |
| `hold` | 保持当前条件等待稳定窗口 |
| `manual_review` | 规则冲突、置信度不足或异常模式，等待人工复核 |
| `stop` | 停止当前实验，不继续采集 |
| `abort_and_release` | 触发安全停止和释放；只能由安全条件或人工命令触发 |

每个动作必须包含原因代码、可读解释、使用的规则版本和关键证据。

## 5. 决策记录

每次决策写入`decisions.jsonl`，至少包括：

```json
{
  "decision_id": "...",
  "timestamp": 0,
  "session_id": "...",
  "milestone": "M1",
  "int_level": "I1",
  "device_state": "ACQUIRE",
  "quality": {
    "label": "weak_signal",
    "confidence": 0.82,
    "valid_duration_s": 4.2
  },
  "action": "retry_same_position",
  "reason_codes": ["INSUFFICIENT_VALID_DURATION"],
  "rule_version": "i1-rules-v0",
  "input_versions": {
    "signal_processing": "s1-v0",
    "configuration": "..."
  },
  "operator_override": null,
  "outcome": null
}
```

后续动作结果回填：

- 是否执行；
- 是否被人工覆盖；
- 新一轮质量是否改善；
- 是否最终接受或停止。

## 6. 成熟度路线

## I0：数字环境固定流程

已由D2/D3提供基础：

- 固定多压力Profile；
- 质量失败阻断；
- 安全状态机；
- ABORT和故障回退；
- 可重放实验报告。

I0只证明模型和规则在数字环境内成立。

## I1：真实单点接受与重采（M1）

I1不自动调整压力，不自动移动探头。

动作范围：

- `accept`；
- `retry_same_position`；
- `reposition`；
- `manual_review`；
- `stop`；
- 安全路径下的`abort_and_release`。

建议首版规则：

1. 安全或设备硬故障：`abort_and_release`；
2. 原始落盘失败、严重丢帧或时间戳异常：`stop`；
3. 持续削顶或传感器断线：`stop`并检查硬件；
4. 有效窗口不足但设备正常：最多重采固定次数；
5. 同位重采仍为弱信号：`reposition`；
6. 规则冲突或PPG对齐异常：`manual_review`；
7. 质量、时长和参考对照均通过：`accept`。

重采次数和阈值必须在看正式结果前冻结，禁止为了让某次数据通过而临时修改。

## I2：压力推荐（M3）

在H2真实多压力数据基础上：

- 根据质量、幅值、形态、削顶和稳定性选择下一压力；
- 当继续增加压力没有收益时停止；
- 检测单调性异常、迟滞和不稳定响应；
- 输出个体有效压力区间和不确定性；
- 保留固定盲扫策略作为对照基线。

## I3：自动施压实验编排（M4）

在H3设备侧安全闭环通过后：

- `hold`等待稳定；
- `continue_scan`进入下一压力；
- `retry_same_position`重新采集当前平台；
- `adjust_pressure`在冻结范围内调整；
- 质量失败时释放或回退；
- 安全事件立即交给设备侧状态机处理；
- 控制成功但信号无效时不得标记实验成功。

## I4：重复性、不确定性与人工复核（M5）

- 检测跨日、重戴和不同操作者下的结果不稳定；
- 识别分布外和低置信度样本；
- 对冲突结果触发`manual_review`；
- 报告决策覆盖率、失败率和人工覆盖率；
- 不把不确定性隐藏为确定结论。

## I5：自动选点（M6）

- 根据空间质量图选择下一位置；
- 判断继续搜索还是接受当前点；
- 输出位置置信度；
- 与人工定位基线比较；
- 失败时回退人工定位；
- 不把单次最大幅值直接等同于最佳位置。

## 7. 规则与模型策略

### 7.1 首选顺序

1. 明确安全规则；
2. 数据完整性硬门；
3. 可解释质量规则；
4. 简单统计和阈值；
5. Logistic Regression、决策树等可解释模型；
6. 数据充分后再评估更复杂时序模型。

### 7.2 不使用LLM直接决策

LLM不得：

- 直接读取原始波形决定是否有效；
- 绕过设备安全状态机；
- 生成压力或位置动作而不受冻结策略约束；
- 输出诊断或治疗建议。

LLM只可基于结构化决策记录生成工程解释、整理失败原因或帮助操作者理解下一步操作。

## 8. 测试

### 8.1 单元测试

- 每个原因代码对应唯一或明确动作；
- 高优先级状态覆盖低优先级状态；
- 达到最大重采次数后不无限循环；
- 规则版本变化可重放；
- 人工覆盖被完整记录。

### 8.2 场景测试

至少覆盖：

- 正常接受；
- 弱信号后同位重采成功；
- 连续弱信号后提示换位；
- 削顶后停止；
- 丢帧或落盘失败后停止；
- PPG对齐冲突后人工复核；
- ABORT和设备故障优先；
- 达到最大重采次数；
- 同一输入重放得到同一决策。

### 8.3 评价指标

- 决策覆盖率；
- 无效记录误接受率；
- 有效记录误拒绝率；
- 重采后改善率；
- 人工覆盖率；
- 平均无效采集次数；
- 决策延迟；
- 相同输入重放一致性；
- 安全规则违反次数，目标必须为0。

## 9. I1验收标准

- 所有正式参数都经过I1接受；
- 质量失败能够触发重采、换位、人工复核或停止；
- 决策原因和规则版本可追溯；
- 同一输入、版本和配置得到相同决策；
- 最大重采次数和停止条件有效；
- 人工覆盖不丢失原始建议；
- 安全和完整性失败不得被质量或效率规则覆盖；
- I1只用于工程采集流程，不产生医学结论。
